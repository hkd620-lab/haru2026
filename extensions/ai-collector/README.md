# AI 지식 수집기 3.0 목적 폴더·자동 분류

개발자 개인용 HARU 연동 수집기다. 설치본 교체와 운영 자동 분류 활성화는 검증 후 진행한다.
기존 로컬 v2.8의 연결 진단·본문 형식·출처 URL 개선을 보존한 뒤 목적 폴더를 추가했다.
`installed-v2.8-baseline.json`은 이관 전 런타임 다섯 파일의 확인용 해시다.

## 목적 폴더

- 의료신기술, 건강상식, 생활정보, 투자정보, AI신기술을 선택할 수 있다.
- 자동 분류를 선택하면 HARU에 저장한 뒤 서버에서 Jev가 처리한다. 확실한 결과는 폴더에, 애매한 결과는 추천과 함께 보류에 모인다.
- 팝업의 선택은 확장 내부에 저장되어 답변 옆 저장 버튼에도 적용된다.
- HARU 학습함에서 폴더별 조회와 수동 이동을 제공한다. 날짜·AI 출처는 별도 정보로 유지한다.
- Jev API 키는 확장에 없으며 서버의 새 자료 생성 처리에서만 사용한다. 직접 선택한 분류는 manual로 저장해 자동 처리가 덮어쓰지 않는다.
- 수동 이동은 HARU 기록의 분류 정보만 바꾼다. 기존 별도 AI 보관함을 동기 이동하거나 원문을 재작성하지 않는다.

관련 웹·Functions를 승인된 순서로 배포하고 합성 자료로 연동을 확인한 뒤에만 확장 설치를 검토한다.
현재 설치 경로와 변경 상태를 확인하고 기존 파일을 별도 보존한 뒤 승인된 3.0 설치본으로 갱신한다. 저장된 사용자 설정·인증 자료는 삭제하지 않는다. 자세한 범위와 확인 절차는 `docs/ai-library-purpose-folders-preview.md`를 참조한다.

## HARU 저장 흐름

1. 선택 본문·출처 URL로 SHA-256 멱등키를 만든다.
2. AI 보관함은 멱등키를 문서 ID로 사용한다. 이미 존재하는 문서(HTTP 409)는 중복 없는 성공으로 처리한다.
3. 확장은 본문을 `chrome.storage.local`에 임시 저장하고 `https://haru2026.com/ai-import#<멱등키>`를 연다.
4. HARU 웹앱이 기존 Firebase 로그인 세션과 검증된 소유자용 callable을 통해 `users/{uid}/records/ai_import_<멱등키>`에 저장한다. 선택한 목적 폴더도 전달한다.
5. HARU 웹앱이 기록을 다시 읽어 존재·타입·출처를 확인한 뒤에만 성공을 표시한다.
6. 확인 성공 메시지를 받은 확장은 임시 payload를 삭제한다.

Firebase 로그인 토큰과 HARU 사용자 UID는 확장에 저장하지 않는다. Firestore 보안 규칙은 기존 본인 UID 제한을 그대로 사용한다.
