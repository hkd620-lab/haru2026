## 재현된 제품 문제

### 1. AI 다듬기 완료 표시와 통계가 저장 중 누락됨 — 중대

일기·육아일기 모두 모의 AI 응답의 본문과 `*_polishedAt`, `*_mode=PREMIUM`은 저장되지만 `*_polished=true`와 `*_stats` 객체는 빠진다. 이 두 기대값이 실패했다.

- 생성 지점: `FormatModal.tsx:2803~2816`, Boolean·객체로 추가한다.
- 누락 지점: `RecordPage.tsx:1085~1090`, `typeof value === 'string'`인 필드만 `updateData`에 옮긴다.
- 사용자가 남긴 본문 자체의 유실은 이번 시나리오에서 없었다. 누락된 통계가 후속 화면에 미치는 영향은 추가 확인 대상이다.
- 제안: 저장 가능한 형식별 필드 타입을 명시해 Boolean·통계도 보존하는 수정과 회귀 검증을 별도 작업으로 진행한다.

### 2. 가계부에서 직접 입력한 제목이 자동 제목으로 교체됨 — 중대

7일 모두 재현됐다. 예: `민준 생활비 1` 입력 → `2026.10.01 · 지출 · 동네마트` 저장. 거래 금액·건수·유형은 보존됐다.

- 원인: `FormatModal.tsx:2487~2509`, `formData`를 펼친 뒤 `household_title`을 `autoTitle`로 덮어쓴다.
- 제안: 수동 기록은 사용자 입력 제목을 우선하고 빈 경우에만 자동 제목을 사용한다. 일괄 가져오기와는 기대 동작을 구분한다.

### 3. 홈의 개인화 문구가 실제 기록과 무관한 고정값 — 중대

일기 1건만 있는 사용자의 다음날 홈에 `연속 기록 12일째`, 어젯밤의 `텃밭일지` 안내가 표시됐다. 미충족 1개다.

- 근거: `HomePageV2.tsx:1385`, `1463` 부근의 고정 문자열과 P01 2번째 진입 시 화면 텍스트 검사.
- 제안: 실제 데이터로 계산하거나 기록이 적은 사용자에게 중립 안내를 사용한다. 홈 수정은 이번 테스트 작업 범위 밖이다.

### 4. 선택하지 않은 날씨·체감기온·기분이 사실처럼 저장됨 — 개선 제안

`비가 온다`는 본문을 썼지만 기본값 `쾌청·쾌적·평온`이 저장·표시됐다.

- 근거: `RecordPage.tsx:302`, `320~321` 기본값과 P01 10월 7일 오전 기록.
- 제안: 미선택 상태를 허용하거나 저장 전에 기본값임을 구분한다. 본문만으로 날씨를 자동 단정하는 방안은 검증하지 않았다.

### 5. 교사의 학급 일기에 ‘육아일기로 정리’를 제안함 — 맥락 검토 제안

교사가 학급 아이들 이야기를 쓴 일기에서 `HARU 육아·교육 비서 → 육아일기로 정리`가 표시됐다. 키워드 설정은 `utils/assistantRecommendations.ts:124~130`이다.

비서 자체는 교육도 다루므로 추천 전체를 오류로 확정하지 않는다. 교사 맥락에서 육아일기 변환이 적절한지는 검토할 필요가 있다. 인수인계에서 언급된 ‘운동→건강관리’는 이번 최종 시나리오에서 따로 재현하지 않았다.

## 하네스 보정과 검증

- 형식/작성 스타일만으로 저장 버튼 문구를 고정하면 일부 형식을 누르지 못했다. 실제 화면에 표시된 버튼을 선택하도록 수정했다.
- AI 저장은 정확한 미리보기 저장 버튼을 선택한다. 저장 완료는 SAYU 상세의 ‘수정하기’ 버튼까지 확인한다. 실제 최종 실행에서는 `/sayu`로 이동했다. 초기 ‘페이지 이동 대신 모달만 열린다’는 추정은 정정한다.
- Playwright 전체 가상 시계 아래에서 AI 결과를 받은 뒤에도 Motion 로딩 오버레이가 남아 클릭을 가로막았다. Date만 이동하고 RAF·performance·타이머는 실제 시계를 유지하자 해소됐다. 이를 제품 장애로 집계하지 않는다.
- SAYU는 목록에서도 형식별 그룹이 접혀 있다. 그룹을 펼치지 않고 제목을 검사했던 가짜 실패를 제거했다.
- 페이지 이동 때 사라지던 모의 호출/쓰기/업로드 증거를 누적한다. 단계 실패 시 해당 인물을 중단하고 오류 원문을 남긴다. 실행 결과에는 단계 실패·중단 여부와 종료 코드도 반영했다.
- [보정 실행 이력](calibration-runs.json)의 네 실행은 확정 제품 결과에 합산하지 않았다. 첫 Chrome 실행은 샌드박스 제한으로 시작하지 못했고, 승인된 브라우저 실행으로 재개했다.
- `npm run build`: 통과, 51.16초. 필요한 Firebase 환경값은 빌드 전용 가짜 값으로 제공했다. 기존 큰 번들/Browserslist 경고가 있으며 배포하지 않았다.
- `git diff --check`: 통과. 이번 수정은 테스트 하네스뿐이며 실제 앱 변경에 대한 통과 판정은 하지 않는다.
