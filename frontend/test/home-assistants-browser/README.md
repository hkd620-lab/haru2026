# 비서실 격리 브라우저 검증

`cd frontend && npm run dev -- --config test/home-assistants-browser/vite.config.mjs`

`http://127.0.0.1:18772/`에서 실제 HomePageV2와 관리 창을 렌더링한다. 인증·Firestore·온보딩·타임라인·성능 기록은 합성 데이터로 대체하며 운영 요청을 보내지 않는다.

- 기본: 하루LAW만 표시, 기록의 전체 보기와 비서실의 전체 보기 독립성.
- `?scenario=existing`: 새 비서실에서 직접 고른 전자소송연습비서 선택 유지, 담기 저장 시 기록 `메모` 보존.
- `?scenario=empty`: 작은 빈 상태, 둘러보기 진입, 등록 없이 실행.
- `?scenario=legacy`: 과거 장부·전자소송 선택이 있어도 하루LAW 1개만 기본 표시. 전체 보기에서 담은 이후에는 직접 고른 목록 유지.
- `?scenario=error`: 저장 실패 시 선택 유지, 관리 창 내부 오류 표시, 재시도 가능.

전체 보기에서 담기·빼기, 관리 창 저장·취소, 휴대폰 폭의 1열 배치를 확인한다. 저장 결과는 상단 output에 표시된다.

## 첫 기록 홈 검증

- 홈 입력란에서 형식을 먼저 선택하고 작성하거나, 작성 후 버튼을 눌러 11가지 형식과 설명에서 선택한다.
- `/record`는 실제 RecordPage다. 형식별 편집창만 합성 수신 창으로 치환하여 전달받은 원문·저장 필드·초안 ID를 표시한다. `합성 기록 저장`은 실제 RecordPage의 저장 처리를 거쳐 모의 서비스로 전달하며 운영 요청은 없다.
- 편집창 닫기 → 기록 내용 유지 → 저장하기 → 다른 형식 선택 시 원문과 초안 ID 보존을 확인한다.
- 홈에서 글을 쓴 뒤 `11가지 형식과 설명 모두 보기` → 형식 타일 선택으로도 원문이 전달되어야 한다.
- 비서 카드 클릭 → 역할 설명 → 비서 열기 또는 내 비서에 담기. 역할을 보기만 할 때는 선택 저장을 호출하지 않는다.
- `?scenario=developer`: 개발자 콘솔의 상단·하단 메뉴 표시. 개발자 UID는 현재 소스에서만 읽는다.
- `?scenario=library-developer`: 기존 검증된 개발자 이메일 조건에 따라 AI 학습함 표시.
- 기본·기존·빈 목록·오류 시나리오에는 개발자 메뉴가 표시되지 않는다.
- `?scenario=guest`: 로그인 전에 작성란은 비활성화되고 로그인 버튼이 제공된다.
- `?scenario=onboarding-pending`: 첫 안내 확인 중에는 작성란이 비활성화되며, 확인 제한시간 뒤 입력 가능 상태로 돌아온다. `onboarding-new`는 첫 안내로 이동한다.
- 320px·390px·데스크톱에서 가로 넘침, 기록 형식과 비서 역할 설명, 대화상자 스크롤과 키보드 닫기를 확인한다.
