## 변경 동작

- 관리 타임라인은 문서 한 개를 카드 한 개로 표시한다. 같은 날짜·내용, 사진만 있는 기록도 개별 삭제/복원한다.
- 삭제/복원은 선택한 `users/{uid}/snsRecords/{id}`의 휴지통 상태와 처리 시각만 갱신한다. 글·날짜·사진 참조와 나머지 원본 필드는 보존한다.
- Firestore 트랜잭션의 읽은 버전 검사에 더해, 화면에서 본 전체 문서의 revision을 비교한다. `updatedAt` 필드를 서버 `updateTime`으로 간주하지 않는다.
- 동일 요청은 공유하고 이미 목표 상태라면 다시 쓰지 않는다. 다른 기기의 변경이나 삭제→복원 이후 도착한 오래된 삭제 요청은 덮어쓰지 않는다.
- 목록 두 곳을 실시간 구독하고 삭제된 문서는 일반 목록에서 제외한다. 관리 화면의 검색결과 저장에서는 휴지통을 제외한다.
- UID가 바뀌면 화면을 새로 마운트한다. 구독/비동기 처리 결과는 현재 Firebase 사용자 객체와 마운트 상태가 일치할 때만 반영한다.
- 서버와 동기화되지 않은 목록에서는 삭제·복원 버튼을 비활성화한다.
- 본문·사진 참조가 비어 있는 중복 문서에 다른 문서의 사진을 임의로 연결하지 않는다.

## 재현

Node 22.18 이상에서 현재 저장소의 `firestore.rules`를 사용하는 로컬 Firestore emulator를 띄운 뒤 frontend에서 실행한다.

```bash

node test/snsRecordsMerge.policy.test.cjs
```

테스트는 loopback 주소와 `demo-haru-sns-trash` 프로젝트만 사용한다. fixture 쓰기는 해당 emulator에서만 발생한다.
