## 3. 이어서 수행한 작업 (6차 대체 수행) — 상세

### 3-1. gardenCrops 실사용 경로 확인
`frontend/src/app/services/firestoreService.ts`의 `getGardenCrops`/`saveGardenCrops`:
```ts
doc(db, 'users', userId, 'settings', 'gardenCrops')
```
→ 실제 경로는 `users/{uid}/settings/gardenCrops` (settings 서브컬렉션 내 고정 문서 1개이며,
`gardenCrops/{docId}`라는 별도 컬렉션이 아닙니다). 이 경로는 이미 기존 규칙
`match /users/{uid}/settings/{settingId} { allow read, write: if request.auth != null && request.auth.uid == uid; }`
로 소유자 보호되고 있었습니다. → 최상위 `gardenCrops/{docId}` 규칙은 **실데이터를 보호하는 규칙이
아니라, 아무도 쓰지 않는 경로에 인증된 누구나 read/write/delete 가능하게 열어둔 순수 유령 규칙**이었습니다.
(vocabulary 사례와 달리 "실경로 보호 누락"은 아니었고, "불필요한 과다 권한 노출"이 문제였습니다.)

### 3-2. 전수 스캔 — 동일 버그 패턴(최상위 소유자미검증 유령 규칙) 탐색
firestore.rules 전체(432줄, 최상위 match 블록 전체)를 직접 읽고, 각 컬렉션의 실사용 경로를
`frontend/src`·`functions/src`에서 대조했습니다.
