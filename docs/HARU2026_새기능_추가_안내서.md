## 1. 새 기록 형식 추가

형식 이름과 저장 필드 접두어(예: 일기 → `diary_*`)는 **형식 등록부** 한 곳에 둔다.

| 순서 | 파일 | 할 일 |
|---|---|---|
| 1 | `frontend/src/app/types/haruTypes.ts` | `RecordFormat` 타입에 형식 이름 추가. 필요하면 `CATEGORY_FORMATS`·`ALL_FORMATS` 에도 추가 |
| 2 | `frontend/src/app/records/formatRegistry.ts` | `FORMAT_REGISTRY` 에 `{ fieldPrefix, keys?, recommendationPriority? }` 항목 추가. 소비처마다 키가 다르면(예: 육아일기 통계 키 `parenting`) `keys` 의 역할(`stats`·`prophecy`·`sayu`)로 적는다 |
| 3 | `functions/src/formats/formatRegistry.ts` | `FORMAT_FIELD_PREFIX` 에 같은 접두어 추가(Functions 는 프런트 파일을 불러올 수 없어 값을 복사한다). 빠뜨리면 `functions/test/formatRegistry.parity.test.mjs` 가 실패한다 |
| 4 | 소비처 형식 범위 목록 | 아래 목록에서 새 형식을 넣을 곳을 고른다(값은 등록부에서 자동으로 읽는다) |

소비처 형식 범위 목록(넣으면 그 기능에 새 형식이 포함된다):

| 기능 | 위치 |
|---|---|
| 형식 통계(형식별·전체) | `firestoreService.ts` `STATISTICS_FORMATS` |
| 기록 내보내기 | `firestoreService.ts` `EXPORT_FORMATS` |
| 공개(같이 보기) 허용 | `firestoreService.ts` `PUBLIC_ALLOWED_FORMATS`, `SayuPage.tsx` `PUBLIC_ALLOWED_FORMAT_KEYS` 목록 |
| SAYU 목록·달력 | `SayuPage.tsx` `SAYU_FORMAT_LABELS`(순서가 필드→형식 판정 순서) |
| SAYU 삭제 라벨 | `SayuModal.tsx` 삭제 처리의 형식 목록 |
| 사진 콜라주 | `TimelineCollageModal.tsx` `FORMAT_PREFIXES` 목록 |
| 기록 입력 | `FormatModal.tsx` `FORMAT_PREFIX` 목록과 `FORMAT_FIELDS`(입력 칸) |
| 합본 보기 | `MergeViewerPage.tsx` `MERGE_VIEWER_FORMATS` |
| 미래전망 | `ProphecyFromRecord.tsx` `FORMAT_PREFIX` 목록 |
| 저장 후 비서 추천 | 등록부 `recommendationPriority`, `assistantRecommendations.ts` `FORMAT_ALIASES` 목록 |
| SAYU 다듬기 그룹(Functions) | `functions/src/index.ts` polishContent 의 `RICH_FORMATS`·`BALANCED_FORMATS`·`CONSERVATIVE_FORMATS` |
| 제목 보정·EPUB(Functions) | `generateTitlesForAll` 의 `FORMAT_PREFIX_MAP`, `epubExport.ts` `FORMAT_PREFIX` |

등록부를 아직 쓰지 않는 곳(새 형식 추가 시 직접 확인): `haruTypes.ts` `FORMAT_EMOJI`, `StatisticsPage.tsx` 카테고리 카드, `FormatStatisticsPage.tsx` `FORMAT_METRICS`, `RecordHubPage.tsx`, `RecordDetailPage.tsx` `FIELD_ORDER`, `config/resultChatConfig.ts` 와 Functions 복제본, `firestoreService.ts` 형식별 통계 switch, `HomePageV2.tsx` `RECORDS`(홈화면 — 8.1 멈춤 조건), `functions/src/snsStory.ts`.

저장 원칙(CLAUDE.md): 기록은 `users/{uid}/records` 에 두고 `date` 는 `YYYY-MM-DD`. 하루 여러 개 생기는 기록은 `{date}_{type}_{timestamp}` 문서 ID 를 쓴다. 우회 컬렉션을 만들지 않는다.

확인할 테스트: `cd frontend && node --import tsx --test test/formatRegistry.test.mjs`, `cd functions && npm run test:format-registry-parity`.

## 2. 새 AI 기능 추가 (AI 호출 창구)

기능 코드는 회사별 SDK 를 직접 만들지 않고 `callAi` 창구 하나만 부른다.

1. `functions/src/ai/aiModels.ts` 의 `AI_ROUTES` 에 용도(purpose)를 추가한다: `{ provider: 'gemini' | 'openai', model, label }`.
2. 함수에서 `callAi({ purpose, input, systemInstruction?, generationConfig?, callOptions? })` 를 부르고, 응답은 `result.text()` 로 읽는다. 키는 창구가 설정 표의 회사에 맞춰 읽는다.
3. 함수 선언에 `secrets: aiSecretsFor('용도')` 를 넣는다(그 용도의 회사 키가 연결된다). `region: 'asia-northeast3'` 를 반드시 적는다.
4. 사용량 기록(`logAiUsage`)의 모델명은 `getAiRoute('용도').model` 로 쓴다.
5. `functions/test/aiGateway.test.js` 의 용도·모델 고정 목록과 호출부 설정 목록에 새 용도를 추가한다(빠뜨리면 테스트가 실패한다).

**모델·회사 교체**는 `AI_ROUTES` 표의 값만 바꾸고 그 용도를 쓰는 함수를 다시 배포하면 된다. 다만 새 AI 호출 추가, 모델·회사 교체, 호출량 증가는 **8.1 멈춤 조건**(허대표님 승인)이다. OpenAI 로 옮길 수 없는 설정(Gemini 전용 도구 등)을 쓰는 용도는 창구가 오류로 막는다.

창구로 아직 옮기지 않은 곳: 하루LAW(`functions/src/haruLaw/`), grammarV2·getGrammarExplain(수정 배포 시 grammarCache 삭제 필요 — 멈춤 조건), 결과물 AI 대화(chatWithResult), snsStory, OpenAI 직접 호출 모듈(bookReview·bookStudio·elderBook).

## 3. 새 비서 추가

| 영역 | 위치·원칙 |
|---|---|
| 프런트 화면·처리 | `frontend/src/app/assistants/<비서>/` 폴더(예: `assistants/haruLaw/HaruLawPanel.tsx`). 한 PR 에 한 기능 |
| Functions | `functions/src/<비서>/` 폴더(예: `functions/src/haruLaw/`)에 두고 `index.ts` 는 다시 내보내기(`export { … } from`)만 한다. 공용 값은 `functions/src/sharedHelpers.ts` |
| 기록 저장 | `users/{uid}/records`, `sourceAgent: '<비서 이름>'` 으로 식별. 새 형식(`formats`)에 넣으면 형식 통계에 섞이므로 비서 기록은 `sourceAgent` 로 구분한다 |
| SAYU 표시 | `frontend/src/app/assistants/sayuAdapters.ts` 의 어댑터로 만든다(SayuPage 에 직접 빌더를 추가하지 않는다) |
| 홈 카드·주소 | `HomePageV2.tsx`·`App.tsx` 변경은 **8.1 멈춤 조건**(허대표님 승인) |

## 4. 작업 절차 요약

1. feature 브랜치에서 작업하고 PR 을 연다.
2. Codex 자동 리뷰 + 독립 Claude 검토자 → 지적은 수정 커밋이나 받아들여진 반박으로 해결.
3. 최신 HEAD CI 통과 → #haru2026-감사 에 8.1 판정① 기록 → 병합(Hosting 자동배포).
4. Functions 는 바뀐 함수만 `firebase deploy --only functions:<이름>` 후 `gcloud functions list` 로 region·updateTime 확인.
5. 멈춤 조건(홈·라우터, 새 기능, 모델·비용, Rules, 저장 경로·마이그레이션, 결제·인증, 운영 데이터 삭제, 8.1 자체 변경)은 병합 전에 허대표님 승인.
