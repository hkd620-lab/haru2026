# 전자소송 제출 후 체크리스트 비서 기능 설계서

## 1. 목적

전자소송 제출 후 사용자가 놓치기 쉬운 사건 진행 확인, 전자송달 확인, 보정명령 대응, 기일 관리, 제출 문서 정리를 돕는 HARU2026 비서 기능의 검토용 설계서다.

이 기능은 법률 판단을 대신하지 않는다. 사용자가 법원 문서와 전자소송포털 안내를 기준으로 해야 할 일을 빠뜨리지 않도록 체크리스트, 알림, 기록 정리를 보조하는 것을 목표로 한다.

## 2. 기본 원칙

- HARU2026의 기존 기록 경로 `users/{uid}/records/{date}`는 절대 변경하지 않는다.
- 전자소송 관련 데이터는 기존 일상기록과 충돌하지 않도록 별도 구조를 검토한다.
- AI는 사건의 법적 결과, 승소 가능성, 기한의 확정 계산을 단정하지 않는다.
- 법령, 법원 문서, 전자소송포털 안내, 사용자가 직접 입력한 사실을 우선한다.
- 비서는 사실 생성자가 아니라 확인, 정리, 알림, 누락 방지 역할을 한다.
- 개인정보와 민감한 소송자료를 다루므로 실제 구현 전 보안과 접근권한을 별도로 검토한다.

## 3. 사용자 흐름 초안

1. 사용자가 전자소송 사건을 등록한다.
2. 사건 기본정보와 제출 완료 정보를 입력한다.
3. 비서가 제출 후 확인해야 할 체크리스트를 생성한다.
4. 사용자가 송달문서, 보정명령, 기일통지, 결정문 등 진행 상황을 기록한다.
5. 비서가 확인 주기와 기한 관련 알림을 제공한다.
6. 사건 종결 또는 보류 상태가 되면 반복 알림을 중지한다.

## 4. 사건 기본정보 항목

- 사건명
- 사건번호
- 법원명
- 사건유형
- 당사자 구분
- 상대방 정보
- 제출일
- 접수번호
- 현재 상태
- 중요 메모
- 첨부 문서 목록

### 사건번호 입력 형식

사건번호는 사용자가 법원 문서에 표시된 형식 그대로 입력한다.

예시:

- 2024가단12345
- 2025차전67890
- 2026머1234
- 2026카단5678

입력 필드는 처음에는 자유입력으로 둔다.  
AI나 프론트엔드가 사건번호를 임의로 정정하거나 법적 의미를 확정하지 않는다.

향후 검색과 필터를 위해 선택적으로 다음 값들을 분리 저장할 수 있다.

- 사건연도
- 사건부호
- 일련번호

단, 1차 구현에서는 자동 파싱을 필수로 하지 않는다.

## 5. 탭 구성 초안

### 5.1 사건정보 탭

사건의 기본 정보를 확인하고 수정하는 영역이다.

표시 항목:

- 사건명
- 사건번호
- 법원
- 사건유형
- 제출일
- 현재 상태
- 최근 확인일
- 다음 확인 예정일

주의: 전자송달 문서는 정기적으로 확인해야 하며, 문서를 열람하지 않아도 법령상 일정 기간이 지나면 송달된 것으로 간주될 수 있습니다. 정확한 효력과 기간은 전자소송포털 안내, 법원 문서, 관련 법령을 기준으로 확인해야 합니다.

### 5.2 제출 후 체크리스트 탭

전자소송 제출 직후 확인할 항목을 제공한다.

기본 체크리스트:

- 제출 완료 화면 확인
- 접수증 또는 제출내역 확인
- 사건번호 부여 여부 확인
- 인지대와 송달료 납부 상태 확인
- 제출서류 PDF 최종본 보관
- 첨부증거 누락 여부 확인
- 나의 사건현황 등록 여부 확인
- 송달문서 확인 루틴 설정

### 5.3 송달확인 탭

전자송달 문서 확인 내역을 기록한다.

기록 항목:

- 송달문서 제목
- 송달 또는 통지 일자
- 열람 일자
- 문서 유형
- 대응 필요 여부
- 대응 기한
- 처리 상태
- 관련 메모

주의: 전자송달 문서는 정기적으로 확인해야 하며, 문서를 열람하지 않아도 법령상 일정 기간이 지나면 송달된 것으로 간주될 수 있습니다. 정확한 효력과 기간은 전자소송포털 안내, 법원 문서, 관련 법령을 기준으로 확인해야 합니다.

### 5.4 보정 및 기한 탭

보정명령, 석명준비명령, 기일통지서, 결정문 등 대응이 필요한 문서를 관리한다.

관리 항목:

- 문서명
- 수령 또는 열람일
- 사용자가 입력한 기한
- 제출해야 할 서류
- 진행 상태
- 제출 완료 여부
- 제출 완료일

비서는 기한을 자동 확정하지 않는다. 사용자가 법원 문서에 적힌 기한을 입력하면 확인 알림과 체크리스트를 제공한다.

### 5.5 문서보관 탭

사건 관련 문서를 분류해 보관한다.

문서 유형:

- 제출서류
- 증거자료
- 송달문서
- 보정서
- 준비서면
- 결정문
- 판결문
- 기타 참고자료

## 6. 알림 트리거 초안

### 6.1 송달 확인 알림

전자소송포털 확인 습관을 돕기 위한 반복 알림이다.

기본 송달 확인 주기:

- 기본값: 매일 1회 확인
- 사용자가 원하면 3일마다, 7일마다로 변경 가능
- 사건 상태가 종결 또는 보류이면 알림을 중지한다.
- 보정명령, 기일통지서, 결정문 등 기한 관련 문서가 있는 사건은 매일 확인을 기본으로 권장한다.

주의: 이 주기는 법률상 기한 계산이 아니라 사용자의 확인 습관을 돕기 위한 알림 주기다.

### 6.2 기한 확인 알림

사용자가 직접 입력한 대응 기한을 기준으로 알림을 제공한다.

예시:

- 기한 7일 전
- 기한 3일 전
- 기한 1일 전
- 당일 오전

단, 법률상 기간 계산, 초일 산입 여부, 휴일 처리, 송달 효력 발생일은 비서가 자동 확정하지 않는다.

### 6.3 제출 완료 후 확인 알림

소장, 신청서, 보정서, 준비서면 등 제출 직후 다음 항목을 확인하도록 안내한다.

- 제출내역 확인
- 접수 여부 확인
- 납부 상태 확인
- 첨부파일 누락 여부 확인
- 제출한 최종 PDF 보관

## 7. 데이터 구조 초안

검토용 예시:

```text
users/{uid}/legalCases/{caseId}
users/{uid}/legalCases/{caseId}/documents/{documentId}
users/{uid}/legalCases/{caseId}/checklists/{checklistId}
users/{uid}/legalCases/{caseId}/alerts/{alertId}
```

`users/{uid}/legalCases/{caseId}` 구조는 기존 HARU2026 일상기록 경로인 `users/{uid}/records/{date}`와 분리하기 위한 검토용 초안이다.

이 구조는 확정된 저장 구조가 아니며, 실제 구현 전에 보안, Firestore rules, 개인정보 처리, 기존 기록 경로와의 충돌 여부를 반드시 재검토한다.

기존 HARU2026 기록 경로 `users/{uid}/records/{date}`는 절대 변경하지 않는다.

### 7.1 legalCases 필드 예시

caseId

partyRole

```

```

## 8. AI 비서 응답 원칙

AI 비서는 사용자가 입력한 사건 정보와 문서 내용을 바탕으로 다음을 수행한다.

- 제출 후 확인 항목 정리
- 누락 가능성이 있는 확인사항 안내
- 사용자가 입력한 기한 기반 알림 설명
- 문서 제목과 사건 진행 메모 정리
- 사용자가 붙여넣은 법원 문서의 체크포인트 요약

AI 비서는 다음을 하지 않는다.

- 승소 가능성 단정
- 법률 효과 확정
- 법정기간 자동 확정
- 사건번호의 법적 의미 확정
- 사용자 입력에 없는 사실 추가
- 법원 문서와 다른 내용 생성

## 9. 위험 문구 제한

다음 표현은 사용하지 않는다.

- 반드시 이깁니다.
- 이 기한까지 제출하면 충분합니다.
- 송달일은 자동으로 확정됩니다.
- 이 사건은 소멸시효가 완성되지 않았습니다.
- 법원은 이렇게 판단할 것입니다.

대체 표현:

- 법원 문서에 기재된 기한을 기준으로 다시 확인하세요.
- 전자소송포털과 법원 안내를 기준으로 확인해야 합니다.
- 필요한 경우 변호사, 법률구조공단, 법원 민원 안내를 통해 확인하세요.
- 비서는 제출 후 확인과 기록 정리를 돕는 보조 도구입니다.

전자송달 관련 문구도 단정하지 않는다. 간주송달 기간과 효력은 사건유형, 적용 법령, 법원 안내에 따라 달라질 수 있으므로 비서가 자동 확정하지 않는다.

## 10. 개인정보 및 보안 검토 필요사항

실제 구현 전 다음 항목을 별도 검토한다.

- 사건번호와 당사자 정보 저장 범위
- 소송 문서 파일 저장 위치
- Firebase Storage 사용 여부
- Firestore rules 접근 제한
- 민감정보 암호화 필요 여부
- 삭제 요청 처리
- 백업과 로그 보관 범위
- AI 처리 시 원문 문서 전송 범위

## 11. 1차 구현 범위 제안

1차 구현은 기능 범위를 좁게 잡는다.

포함:

- 사건 등록
- 사건 기본정보 표시
- 제출 후 체크리스트
- 송달 확인 메모
- 사용자가 입력한 기한 기반 알림

제외:

- 법률상 기한 자동 계산
- 사건번호 자동 해석
- 전자소송포털 자동 로그인 또는 스크래핑
- 법률 판단 자동화
- 기존 기록 경로 변경

## 12. 검수 체크리스트

구현 전 확인:

- 기존 기록 경로 `users/{uid}/records/{date}`를 변경하지 않는가?
- `legalCases` 구조가 확정이 아닌 검토용 초안으로 표시되어 있는가?
- Firestore rules 설계가 별도로 검토되었는가?
- AI가 법률 판단을 단정하지 않는가?
- 전자송달 간주송달 문구가 충분히 주의 문구로 표시되는가?
- 사건번호 입력이 자유입력으로 유지되는가?
- 알림 주기가 법률상 기한 계산으로 오해되지 않는가?

## 13. 결론

전자소송 제출 후 체크리스트 비서는 HARU2026의 하루LAW 흐름 안에서 사용자의 법률 관련 기록을 안전하게 정리하고, 제출 후 확인 습관을 돕는 보조 기능이다.

핵심은 법률 판단 자동화가 아니라 누락 방지, 송달 확인 습관, 문서 정리, 사용자 입력 기반 알림이다. 실제 구현 시에는 기존 HARU2026 기록 경로를 보존하고, 별도 법률 사건 데이터 구조는 보안과 Firestore rules 검토 후 확정해야 한다.
