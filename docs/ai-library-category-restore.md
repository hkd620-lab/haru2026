# AI 목적 폴더의 명시적 복원

## 범위

다섯 목적 폴더 자동 분류와 이후 수동 이동을 유지한다. 취소는 새 전송·반영을 중단하고, 불확실 상태 정리는 진행 중 항목을 `unknown`으로 바꾼다. 두 동작 모두 이미 반영된 폴더를 되돌리지 않는다. 새 `restore` 동작만 이 작업의 이전 분류를 복원한다. 전송된 자료와 이미 발생했을 수 있는 비용은 되돌릴 수 없다.

이 보완은 로컬 구현·가짜 provider·격리된 Firestore 에뮬레이터 검증이다. 실제 자료·API 호출, 키 접근, runtime 활성화, Rules 변경, push·병합·배포를 포함하지 않는다.

## 정확한 이전 상태와 보호 장치

- 실제 분류 반영 트랜잭션에서 `aiCategory`, `aiCategorySource`, `aiCategoryAuto` 각각의 필드 존재 여부와 전체 값을 보존한다. 전송 예약 시점의 오래된 값이나 JSON 변환·축약본으로 복원하지 않는다.
- 복원 자료는 기존 서버 전용 저장소의 `jobs/{manifestHash}/restorations/{recordId}`에 개별 문서로 보관한다. 작업 응답에는 복원 결과만 포함하고 이전 메타데이터를 반환하지 않는다.
- 문자열·수치·불리언·null·배열·일반 맵·Timestamp·GeoPoint·bytes·DocumentReference를 그대로 유지한다. 보수적 크기 한도 32KiB와 깊이 제한을 초과하거나 지원하지 않는 타입이면 분류 반영 전 거부하고 검토 대상으로 남긴다. 이미 확보한 호출 시도와 비용은 유지한다. 작업 문서에 수백 개의 스냅샷을 넣지 않는다.
- 기록의 Firestore `createTime`으로 삭제 후 같은 ID에 다시 생성한 기록을 구분한다. 전송 허가와 최종 반영에도 이 식별자를 확인한다.
- 복원 자료 생성과 기록 분류 변경을 같은 트랜잭션으로 커밋한다. 복원 시 기록의 현재 `updateTime`이 복원 자료 문서의 불변 `createTime`과 같아야 한다. 자료 문서 자체도 수정되지 않았어야 한다. 본문 해시와 실제 적용된 세 필드 전체 값도 비교한다.
- `serverTimestamp()` 변환값은 commit updateTime보다 정밀도가 낮을 수 있어 버전 비교에 쓰지 않는다. 에뮬레이터에서 이 차이를 확인한 뒤 위의 동일 커밋 문서 생성 시각 비교로 검증했다.
- 이후 수동 이동, 새 AI 분류, 본문 수정, 수정 후 같은 값으로 되돌림, 관련 없는 필드 저장도 보수적으로 복원 제외한다. 사용자의 나중 변경을 덮어쓰지 않는 것을 우선한다.
- 복원은 세 필드만 갱신하거나 삭제한다. 본문·날짜·AI 자료 출처·책 정보·`aiCategoryUpdatedAt`은 쓰지 않는다. 필드 부재와 명시적 null도 구분한다.

## 재시도와 화면

첫 복원 요청이 작업을 취소 상태로 고정한다. 이후 최대 25개 항목을 항목별 트랜잭션으로 처리하며, 기록 복원과 `restored`/`skipped`/`unavailable` 결과를 함께 커밋한다. 중간 오류·중복 클릭·동시 요청·재시작은 이미 완료한 항목을 다시 쓰지 않는다. 이전 축약 이력만 남은 작업은 `unavailable`로 표시하고 추측 복원하지 않는다.

복원은 소유자 인증 아래 승인 만료·철회나 runtime 비활성 상태에서도 가능하며 provider를 생성하거나 키를 조회하지 않는다. 전역 시도 이력·예약 금액·기존 승인 범위를 삭제·환불·재활성화하지 않는다. 복원 후 같은 자료로 새 계획을 만들어도 기존 시도 키 때문에 유료 요청을 반복하지 않는다.

화면에는 별도 확인란과 복원 버튼, 복원·제외·불가·미처리 개수가 있다. 응답을 잃으면 자동 재시도하지 않고 먼저 상태를 조회한다. 계정 전환·새로고침 후 자동 분류나 복원을 시작하지 않는다. 새 계획으로 넘어간 이전 작업의 해시는 같은 탭의 계정별 sessionStorage 이력에서 다시 선택할 수 있다. 탭 종료·저장소 삭제·다른 기기까지 복원 작업 목록을 제공하는 서버 이력 화면은 이번 범위가 아니다.

## 검증

- Functions 소스 시험: `npm run test:ai-library-classification`.
- 실제 Store 어댑터 시험: `AI_LIBRARY_TEST_PROJECT=demo-haru-ai-classification FIRESTORE_EMULATOR_HOST=127.0.0.1:<port> npm run test:ai-library-classification:emulator`. 가짜 provider만 사용한다.
- 복원 시험은 존재/부재/null와 Firestore 원시 타입, 최종 반영 직전 메타데이터 변경, commit 버전, 나중 수정·동일 값 재생성, 불충분한 과거 이력, 크기 제한, 부분 중단·동시 복원/취소/복구, 수동 이동 경합, in-flight 결과와 전송 중복 방지를 포함한다.
- 프런트엔드 소스 시험과 `classification.html`의 합성 React 화면은 별도 검증한다. 실제 브라우저·운영 서비스 검증 및 최신 PR 검토/CI와 구분한다.
