판정: 승인

PR #294의 MergePage 수정과 회귀 테스트를 실제 파일로 확인했습니다. 새로 생긴 회귀나 등급 우회, 기간 정책 누락은 찾지 못했습니다. 판정이 '수정 후 승인'이 아니므로 수정 후 승인 횟수는 3회 그대로입니다.

## 1. 수정 코드 확인

```tsx
// MergePage.tsx:67
const [selectedPeriod, setSelectedPeriod] = useState<MergePeriod>('monthly');
// MergePage.tsx:111-114
const thirtyDaysAgo = new Date();
thirtyDaysAgo.setDate(thirtyDaysAgo.getDate() - 30);
setStartDate(getStatsPeriodRange('month', new Date()).start);
setLedgerVatStart(getLocalDateString(thirtyDaysAgo));
// MergePage.tsx:356-359
if (!canUsePeriod(selectedPeriod)) {

  return;
}
```

- **화면 표시와 실제 실행 범위가 이제 같습니다.**
  - 기본으로 '이번 달'이 선택돼 있고, 시작일도 `getStatsPeriodRange('month')`가 주는 이번 달 1일입니다(`recordStats.ts:139-141`).
  - 종료일은 오늘입니다. 기간 버튼을 누를 때 쓰는 `handlePeriodSelect`(`:138-147`)와 같은 함수를 써서 계산 기준이 하나뿐입니다.
- **무료 사용자에게도 기본값이 허용됩니다.** `month`는 무료에서 쓸 수 있습니다(E2E 표와 `canUseStatsPeriod` 일치). 그래서 기본 상태가 잠금으로 막히지 않습니다.
- **실행 직전 확인이 기록 조회보다 먼저 일어납니다.** 이 확인(`:356`)은 `setIsRunning`(`:371`)과 `getRecords`(`:374`)보다 앞에 있습니다. 화면을 연 뒤 구독이 바뀌어도 기록을 읽지 않고 중단합니다.
- **보조장부 날짜는 그대로입니다.** `ledgerVatStart`는 계속 최근 30일입니다. `thirtyDaysAgo`는 이제 보조장부에만 쓰입니다.
- **합본 뷰어는 바꿀 필요가 없습니다.** `MergeViewerPage`는 넘겨받은 `startDate`/`endDate`만 사용합니다(`:65,134,152`).

## 2. 등급 우회 여부: 우회 경로 없음

- 잠긴 기간 버튼은 선택되지 않고 구독 화면으로 보냅니다(`:680-685`). 이 부분은 이번 변경 전과 같습니다.
- 직접 날짜를 입력하는 칸은 `selectedPeriod === 'custom'`일 때만 보입니다(`:725`). `custom`은 버튼 잠금을 거친 뒤에만 선택됩니다. 그래서 무료·베이직 사용자가 날짜를 직접 넣을 방법이 없습니다.
- 구독 정보가 아직 불러와지지 않았을 때 기본값은 `free`입니다(`useSubscription.ts:105`). 기본 선택인 `monthly`는 무료에서 허용되므로, 불러오는 중에 정상 사용자가 잘못 막히지 않습니다.
- 개발자 계정은 `premium`/`active`로 처리됩니다(`:62-68`). 새로 추가된 확인에 개발자가 막히지 않습니다.

## 4. 규모·멈춤 조건·승인 범위

- **규모: 소규모입니다.** 파일 하나에서 버그 하나를 고쳤고, 기본값 1줄·날짜 계산 1줄·실행 전 확인 4줄과 테스트입니다.
- **멈춤 조건: 해당 없음.**
  - Functions, 저장 경로, Rules, 결제, 인증, AI 모델, 라우터, 홈 화면 변경이 없습니다.
  - 커밋 메시지("합본 기본 기간과 실행 권한 검증 보완")가 실제 변경과 맞습니다.
- **승인 범위:** 대표님은 통합·합본 작업을 "검토 통과 후 병합·배포 승인"하셨고, 최근 지시도 "E2E를 가능한 범위에서 계속 진행"입니다.
  - 이번 수정은 그 E2E에서 찾은 합본 기간 정책(결정 ⑥) 누락을 같은 기능 안에서 보완한 것입니다. 프론트엔드만 바뀌어 Hosting 자동배포만 일어납니다. #293과 같은 성격입니다.
  - 8.1절 판정①로 병합과 Hosting 배포를 진행하면 되고, 대표 승인을 새로 받을 필요는 없다고 판단합니다.
  - 단, Functions(`exportEpub` 등) 배포가 같이 일어나면 이 판단 범위 밖입니다.

## 5. 이번 변경에서 생긴 비차단 지적

1. **기본 선택값은 단위 테스트가 확인하지 않습니다.** 테스트는 `handleRunMerge`만 잘라서 실행합니다. 그래서 `useState('monthly')`와 시작일 계산이 맞는지는 브라우저 E2E 증거로만 확인됩니다. 필요하면 소스 문자열을 검사하는 테스트 하나를 더하면 됩니다.
2. **화면을 연 채 날짜가 바뀌면 옛 범위로 실행됩니다.** 예를 들어 10/31에 화면을 열고 11/1에 실행하면 10/1~10/31로 실행됩니다. 기간 길이는 그 등급의 허용 범위 안이라 등급 우회는 아니지만, '이번 달'이라는 표시와는 어긋납니다. 원래부터 있던 동작이고 이번 변경으로 나빠지지 않았습니다.
3. **경고 문구에 어떤 등급이 필요한지 나오지 않습니다.** 버튼에서는 `accessLabel`(예: 베이직부터)을 보여 주지만, 실행할 때 경고는 일반 문구만 보여 줍니다. 사용성 문제입니다.
