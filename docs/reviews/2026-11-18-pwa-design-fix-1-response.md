# PR #407 1차 지적 반영 및 재검증

## 승인 범위와 검토 원문

대표님의 2026-11-18 이 채팅 원문: “호박은 하루랩 공식로고로 하자 포도로고사용하자 나머지는 기장의 의견을 승인한다 지금 바로 묶음으로 작업진행해”, “9시 이후 독립검토 받고, 지적사항이 있으면 수정·재검증까지 마무리해서 결과 알려줘.” 이후 사용량 제한 해제를 알려 즉시 독립 검토를 요청했다. 이 승인 범위에서 구현과 지적 수정·검증·작업 브랜치 Git을 수행한다. main 병합·운영 배포는 하지 않는다.

독립 3차 원문: `2026-11-18-pwa-design-claude-review-03.md`(수정 후 승인 1회). Codex 1차: `2026-11-18-pwa-design-codex-review-01.md`(대상 c1ae245f, 지적 4개). 이전 두 실행 실패 원문은 `2026-11-18-pwa-design-claude-unavailable.md`에 보존한다. 결과 없는 시도는 수정 후 승인 횟수로 세지 않는다.

## 검증 근거

- 제품 빌드: QA용 Firebase 환경값으로 npm run build. 실 운영 API/계정에 연결하지 않음. 생성물은 배포용 아님.
- 확장 단위 시험 107개 중 101개 통과, 이전 main 원본에서도 동일하게 재현한 기존 성장타임라인 하네스 6개 ReferenceError만 남음. 원본 대조는 최초 보존 로그를 유지.
- 빌드 SW 실행 시험 4개: 네비게이션 제외, 공개 캐시, 강제 활성화 부재, Hosting Functions rewrite 자동 대조.
- PWA 실제 SW 검증: test/pwa-browser는 제품 등록·업데이트 제어·PwaStatus 모듈을 그대로 사용. worker의 공개 버전 주석만 바꿔 갱신을 모의. 운영 연결 없음. 최초 제어 이벤트 지연 회복 및 일반 업데이트에서 타 탭 입력 보존 확인. 이후 연속 업데이트 상태·늦은 실패 차단은 추가 단위 시험으로 확인.
- 브라우저 native confirm 제어가 멈춘 첫 시험은 성공으로 세지 않음. 사용자에게 확인창 닫기를 요청한 뒤, 접근 가능한 앱 내 확인창으로 변경하여 새 시험 origin에서 완료.
- Chrome viewport override가 실제 폭을 바꾸지 않아 모바일 검증에 포함하지 않음. 대신 실제 width 390/320 iframe 미디어 쿼리와 DOM 좌표를 사용. 실기기 설치·기존 운영 SW에서 전환·Google 실제 OAuth 완료·iOS 키보드/노치·상태바는 별도 운영 E2E 대기.
- 원본 프로젝트와 다른 CC 세션은 수정·재개·종료하지 않음. 격리 worktree의 파일만 수정.

최신 구현 HEAD에 대한 Codex 재검토와 독립 Claude 재검토가 끝나기 전 판정①이나 운영 완료로 처리하지 않는다.
