# 독립 Claude 설계 검토 — 가계부 파일 가져오기 1단계 (1회차)

**판정: 수정 후 승인**

- 이 건의 "수정 후 승인"은 이번이 **1회차**입니다. 정책 8.1에 따라 상한은 3회입니다.
- 대상은 HEAD `c37ff624`, 설계 02, 그리고 03에 적힌 기장 보완 의견입니다.
- 파일·Git·게시는 일절 하지 않았습니다. 이 세션에는 쓰기 도구가 없어 결과를 이 답변으로만 드립니다. 원문은 실행자가 `docs/reviews/`에 새 파일로 남겨야 합니다.

**재설계가 아닌 이유:** 뼈대는 맞습니다. 저장·중복 서비스를 그대로 쓰고, 기존 거래 뒤에 덧붙이기만 하며, 카드 파서는 가계부 전용으로 새로 만들고, Function은 부르지 않습니다. 고칠 것은 키·금액·연도·헤더 규칙, 그리고 화면 쪽 검사입니다.

## 코드 확인 요약

- **기존 데이터 보존은 코드로 확인됨.** 저장은 기존 배열 뒤에 덧붙이기만 합니다(`householdSaveService.ts:114`). "이미 저장됨"은 건너뜁니다(:96). 저장 직전에 트랜잭션 안에서 다시 판정합니다(:79-91). 529건·메모·분류가 재가져오기로 덮어써질 경로는 없습니다.
- **다른 파일끼리 겹치는 거래는 이미 "의심"으로 잡힘.** 같은 파일 안의 행끼리만 비교에서 빠집니다(`householdDuplicates.ts:74-78`). `importSource.kind`로 갈라지는 코드는 없어서 타입을 넓혀도 영향이 없습니다(grep 결과 정의 1곳만).
- **저장 서비스 검사가 좁음.** 날짜·거래종류·금액·지출 사용처만 봅니다(:65-66). 결제수단·카드종류·확인 선택은 검사하지 않습니다. 그래서 화면 쪽 검사가 유일한 차단막입니다.
- **카드 파일이 복호화 Function으로 갈 수 있는 경로가 있음.** ZIP이 아닌 엑셀에 암호가 입력돼 있으면 `decryptKakaoXlsx`를 부릅니다(`FormatModal.tsx:2964-2969`). 지금은 확장자 검사(:2927 `xlsx|pdf`)만 `.xls`를 막고 있습니다.
- **실제 국민카드 형식 근거가 없음.** `frontend/test`에서 국민·KB·"이번달 결제금액"을 검색하면 0건입니다. 02가 말한 "기존 합성 형식"이라는 근거는 없고, 열 이름은 추정입니다.
- **보조장부 파서는 위험해서 그대로 쓰면 안 됨.** 청구금액을 우선 사용하고(`ledgerPeriodImport.ts:483-507`), `\d+건`이 들어간 행을 합계 행으로 보고 버립니다(:438). 가계부에 재사용하면 안 됩니다.

## 필수수정 (M1–M12)

**M1 거래 키**
- 카드 키는 `card:kb:` + 해시(fileDigest, 시트번호, 원본 행번호)로만 만듭니다.
- 승인번호는 키에도, 저장 데이터에도 넣지 않습니다.
- 다른 파일과의 겹침은 기존 "의심" 판정으로 처리합니다.
- 02 §3-3의 승인번호 키와 §5의 "승인번호면 이미 저장됨"은 삭제합니다.

**M2 금액 기준은 이용금액 하나**
- `amountBasis` 선택과 `billed`를 없앱니다.
- 머리글에 `이번달결제금액`·결제원금·회차 같은 청구서 열이 있으면 **파일 전체를 미지원으로 거부**합니다.
- 할부: 이용내역의 이용금액을 그대로 저장하고 "구매 전체금액으로 기록" 안내를 붙입니다. 할부 값을 읽지 못하면 저장할 수 없습니다.
- 외화: 현지금액이나 통화 열에 값이 있거나 원화 금액이 없으면 **선택할 수 없게** 하고 직접 입력하라고 안내합니다.
- 취소:
  - 음수나 괄호 금액은 음수 지출로 저장하고 안내를 붙입니다.
  - 상태가 취소인데 금액이 양수면 기본은 미선택·저장 차단입니다. 사용자가 "취소(음수)로 기록" 또는 "제외"를 명시적으로 골라야 합니다.
  - 상태 값을 알아보지 못하면 저장할 수 없습니다.
- "시범"이라는 표시가 이 규칙들을 면제하지 않습니다.

**M3 연도**
- 연도가 들어 있는 날짜만 받습니다.
- MMDD 형식 행이 하나라도 있으면 파일 전체를 거부합니다.
- 올해를 기본값으로 쓰지 않고, `normalizeLedgerDate`의 기준연도 경로도 쓰지 않습니다.

**M4 지원 헤더를 엄격하게 검사**
- 필수 열: 날짜, 가맹점, `이용금액`(정확히 이 이름. `금액`·`결제금액`은 안 됨), 상태.
- 하나라도 없으면 파일 전체를 거부합니다.
- 날짜는 있는데 금액·사용처를 못 읽는 행이 1건이라도 있으면 **파일 전체를 저장하지 않습니다.** 카카오 PDF와 같은 원칙입니다(00-baseline 17번 테스트).
- 합계 행으로 보고 버리는 것은 날짜 칸이 비어 있고 합계·소계 문구가 있는 행만입니다.

**M5 저장 검증 우회 차단**
- 저장 처리 함수 안에서 `saveHouseholdEntriesBatch`를 부르기 직전에, 실제로 보낼 entries를 순수 함수로 다시 검사합니다. 버튼을 꺼 두는 것만으로는 부족합니다.
- 검사 항목: 카드종류 선택 여부, M2 확인 미결, 차단된 행 포함 여부.
- 막힌 행은 금액을 `''`로 두어 저장 서비스가 한 번 더 거부하게 합니다.
- 중복 확인 후 다시 저장할 때도 같은 검사를 거칩니다.

**M6 기관 선택과 Function 차단**
- 파일을 고를 때 `{file, sourceId}`를 함께 고정합니다.
- 파일 선택·읽기·미리보기·저장 중에는 기관 선택을 막습니다.
- 기관을 바꾸면 미리보기, 중복 확인 결과·선택, 카드종류, 확인 선택을 모두 초기화합니다.
- 카드 경로:
  - `httpsCallable`을 쓰지 않고 암호 입력도 받지 않습니다.
  - ZIP·CFB(.xls 형식)만 기기 안에서 읽습니다.
  - 암호 오류가 나면 "암호 없는 파일로 받아 주세요"라고 안내합니다.
  - `.pdf`는 거부합니다.
- 카카오 경로의 `xlsx|pdf` 검사는 그대로 둡니다.
- 카드 파서 모듈은 firebase/functions를 import하지 않습니다.

**M7 계정 전환**
- 카드 경로에도 카카오와 같은 세 번의 세션 확인을 넣습니다(:2975, :2988, :2995).
- 새로 생기는 카드 관련 상태는 모두 세션 초기화 대상에 넣습니다.

**M8 카드대금**
- 후보는 지금 미리보기 중인 **새 은행 행에만** 표시합니다. 바꾸는 방법은 기존 `changeKakaoTransactionType`입니다.
- 이미 저장된 거래는 바꾸지 않습니다.
- 카드 미리보기에 "미해결" 안내를 붙입니다:
  - 이미 저장된 은행 카드대금
  - 승인일과 출금일이 다른 체크카드 거래
  - 카드대금 합산

  이 세 가지는 자동으로 판정하지 않으며 합계가 이중으로 잡힐 수 있다고 알립니다.

**M9 기관 안내표**
- 상태는 현재지원 / 시범 / 미지원 세 가지로 구분합니다.
- 카카오뱅크 엑셀·PDF: **현재지원**. 01의 공식 링크 2개와 확인일을 표시합니다.
- 국민카드: **시범**. 02의 빈 배열 대신 기장이 확인한 사실만 씁니다.
  - 경로: "홈페이지 MyKB > 카드이용 > 이용내역·매출전표"
  - 링크: `https://card.kbcard.com/MKB/DVIEW/HMBMCXPRIMYS0007`
  - "로그인 뒤 엑셀 저장 버튼과 앱 다운로드는 확인 전"이라고 함께 표시합니다.
- 저는 웹에 접근할 수 없어 이 URL을 직접 확인하지 못했습니다. 구현하는 날 다시 확인해야 합니다.
- 국민카드 PDF, 암호 걸린 카드 엑셀, 다른 기관은 **미지원**입니다.

**M10 장부 정정**

- `NEXT_HANDOFF.md:61`의 9번 자동연동은 35 문서로 대체됐습니다.

## 권고 (R1–R5)

- **R1** PR을 둘로 나누거나 커밋을 1-A / 1-B·C로 분리합니다. 안내표는 먼저 배포할 수 있습니다.
- **R2** 배포 전에 허대표님께 실제 국민카드 이용내역 엑셀의 **머리글 행만** 받아 형식을 대조합니다(거래 데이터 없이). 그래야 "항상 거부되는 기능"이 배포되는 일을 막습니다.
- **R3** 카드 미리보기에 이미 저장된 카드대금 후보를 **읽기 전용**으로 보여 줍니다. 변경 기능은 넣지 않습니다.
- **R4** 새 필드 `transferKind`는 빼서 범위를 줄입니다. 합계는 이미 이체를 제외합니다.
- **R5** 다른 파일과 겹치는 행이 많을 수 있으니, 기존 "모두 제외" 일괄 선택을 카드 미리보기에도 그대로 연결합니다.

## 규모와 멈춤 조건

**규모는 대(大)입니다.** 정책의 "대규모 새 기능 착수"에 해당합니다. 다만 35 문서에 기록된 허대표님 직접 승인이 이 범위를 덮으므로 착수는 가능합니다. 판정 기록에는 그 승인 원문을 인용해야 합니다.

**병합·Hosting 배포 근거:** 8.1은 새 CC 세션이 2026-10-07 승인을 이어받지 못한다고 정합니다. 그래서 근거는 이번 직접 승인이며, 판정①을 받은 경우에만 해당합니다.

**멈추고 허대표님께 보고할 조건:**
- 실제 국민카드 형식에 상태 열이나 연도 포함 날짜가 없을 때
- 이용금액 열 이름이 다를 때
- 저장·중복·합계 서비스를 고쳐야 할 때
- 이미 저장된 거래를 바꿔야 할 때
- Function을 부르거나 고쳐야 할 때
- Rules·비용·라우터·모바일 변경이 생길 때

**운영 완료 판정:** 실제 파일과 실기기 확인이 필요하므로 🔍(추가 E2E 필요)로 남깁니다.
