**N4 blocked와 파일 전체 거부의 경계를 명확히 (06 M2와 M4의 충돌 해소)**

06에는 "원화 이용금액이 없으면 blocked"(M2)와 "날짜는 있는데 금액을 못 읽으면 파일 전체 거부"(M4)가 함께 있습니다. 순서를 다음처럼 정합니다.

1. 상태나 날짜를 판독할 수 없음 → 파일 전체 거부
2. 이용금액 칸에 값이 있으나 엄격 정규식에 맞지 않음 → 파일 전체 거부
3. 이용금액이 비어 있고, 현지금액이나 통화 칸에 값이 있음 → blocked
4. 이용금액이 비어 있고, 외화 근거도 없음 → 파일 전체 거부

blocked는 **외화로 식별된 행에만** 씁니다.

**N5 원화가 아닌 통화기호는 엄격 거부**

- 이용금액 텍스트에 `$`, `€`, `¥`, `£`, `USD` 같은 영문 통화코드, 소수점이 있으면 파일 전체를 거부합니다.
- 허용하는 형식은 숫자, 쉼표, 앞의 `-`, 괄호, 끝의 `원`뿐입니다. `₩`도 허용 목록에 넣지 않습니다.
- 엑셀 숫자 셀은 값만 보지 않습니다. 셀 서식(`z`)이나 표시 문자열(`w`)에 원화가 아닌 통화기호가 있어도 거부합니다.
- 테스트: `$12`, `12.50`, 서식이 USD인 숫자 셀 → 각각 거부

**N6 사전 확인과 카드종류는 파일을 읽을 때 고정**

- 카드종류(신용/체크)는 사전 확인 체크와 함께 **파일 선택 전에** 고릅니다. 둘 다 되어야 파일 선택이 켜집니다.
- 파싱할 때 `cardImportContext{confirmedApproval, cardType, fileDigest}`에 고정합니다. 고정된 뒤에는 두 입력을 끕니다.
- 바꾸려면 "다시 선택"을 눌러야 합니다. 그러면 기관을 바꿀 때와 같이 전부 초기화하고 파일을 다시 읽습니다.
- 카드 행의 결제수단은 context에서 가져오고, 미리보기에서는 읽기 전용으로 둡니다.
- 테스트:
  - 읽은 뒤 카드종류를 바꾸면 미리보기가 초기화됨
  - context와 entry의 결제수단이 다르면 검증 함수가 차단

**N7 취소 선택은 저장 함수에서도 순수 검증**

- `:3072` 토글에도 막는 조건을 넣습니다: blocked, needsChoice 미결, `cancelChoice==='exclude'`. `:3080` 모두 선택에도 같은 조건을 넣습니다.
- `validateHouseholdImportSave`에 다음을 명시합니다.
  - needsChoice 행은 `cancelChoice==='negative'`이고 `amount === -|expectedAmount|`일 때만 통과합니다.
  - 그 밖의 조합은 모두 차단합니다: 선택값이 negative인데 금액이 양수, `exclude`인데 선택됨, `cancelChoice` 없음.
  - `cancelChoice`는 전용 처리 함수에서만 바꿉니다.
- 테스트: 위 세 조합 차단, 모두 선택 뒤에도 needsChoice는 미선택

**N8 '카카오 영향 없음'의 뜻을 정정하고 회귀 검증 추가**

- 06의 "바뀌는 것은 타입 확장뿐"을 고칩니다. 바른 뜻은 "카카오 파서, 저장 payload, 합계는 바뀌지 않는다"입니다.

  - 같은 합성 카카오 파일을 넣고 후보 버튼을 누르지 않으면, 파서 출력·저장 entries JSON·월 합계가 변경 전 기준과 같음
  - 후보 표시는 entry를 바꾸지 않음
  - 검증 함수에 카카오 entries를 넣으면 그대로 통과
  - 00-baseline 44건과 빌드
