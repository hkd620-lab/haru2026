## 진단과 경계

IAM 정책을 변경 없이 읽어 GitHub Actions용으로 명명된 서비스 계정에 Hosting 관리자 역할만 부여된 상태를 확인했다. 그러나 로그에서 마스킹된 실제 CI 인증 주체와 이 계정의 동일성을 확정하지 못했다. 요청 시각의 Service Usage 거부 감사 로그 조회도 결과가 없었다. **특정 계정/역할 부족이 유일한 근본 원인이라고 확정하지 않는다.** 실제 배포 인증 주체·서비스 조회 권한·정책을 추가 대조해야 한다.

403 확인은 GitHub 실패 로그로 확인한 사실이며 제품 옵션 분기나 웹 컴파일 실패가 아니다. IAM·인증 정책·GitHub Secret·workflow·CLI 버전을 수정하거나 서비스 API를 활성화하지 않았다. 원본 로그의 지원용 opaque token, 마스킹된 인증 문맥, IAM 전체 바인딩은 이 공개 기록에 복사하지 않았다.

최초 `gh run view --log-failed`는 로컬 cache 쓰기 권한 때문에 실패했고, 권한을 받은 후에는 로그가 없는 Deploy Preview check도 선택해 `log not found`가 반환됐다. 실제 job ID를 지정해 `--log-failed`로 원인을 확인했다. 이 로컬 로그 조회 실패들은 CI 재실행/새 배포 시도가 아니다.
