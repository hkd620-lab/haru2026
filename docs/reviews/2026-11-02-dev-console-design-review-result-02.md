## P1-1 반박 판단

**결론은 수용합니다. 다만 근거 하나는 그대로 받아들이지 않습니다.**

독립 대조 결과는 다음과 같습니다. main src와 HEAD src를 임시 폴더에 각각 컴파일했습니다.

- HEAD의 `functions/lib/index.js`와 HEAD src 컴파일 결과가 SHA-256 기준으로 일치합니다.
- 산출물에서 사라진 파일은 `englishBibleWordMeaning.js`와 `grammar/` 5개 파일입니다.
- 바뀐 파일은 `index.js`, `ai/aiModels.js`뿐입니다.
- `index.js`의 추가 줄은 export 초기화 2줄과 `const { word } = request.data || {};` 1줄입니다.

| CC 근거 | 판단 |
|---|---|
| 전용 코드 제거를 위해 재생성·삭제가 필요 | **수용.** 기준 `lib/index.js`는 64행에서 전용 모듈을 require하고, 원요구는 전용 코드 제거 |
| require 정합성 때문에 필요 | **부분 수용.** 전용 모듈만 지우면 깨지는 것은 맞음. 다만 `lib/` 전체를 그대로 두는 것도 그 부분은 정합적이었으므로, 결정적 근거는 전용 코드 제거 요구임 |

- **실행 가능성:** 추적 중인 `lib/`는 기준에서도 이미 실행 불가능했습니다. `lib/index.js`의 로컬 require 28개 중 19개가 미추적이었습니다. HEAD는 34개 중 26개로 숫자는 늘었지만 상태가 달라지지는 않습니다.

## 추가 코드 검토 결과

- **공통 fallback:**
  - `<Route path="*" ...>`은 하나뿐이고 라우트 표의 마지막입니다.
  - 내부 이동 대상 중 라우트가 없는 것은 정적 경로 `/welcome`, `/tools/blog-neighbor-assistant`뿐입니다. `/welcome`은 Hosting rewrite를 쓰는 전체 페이지 이동입니다.
  - PWA는 `navigateFallback: null`이라 `/welcome`, `/card`, `/tools/...`, `/oauth/google/callback`이 SPA fallback으로 빨려 들지 않습니다.
  - 결제 복귀 URL과 sitemap의 앱 경로도 라우트가 있습니다.
- **`HARU주식` 비서 카드 제거:** 기준에서 이미 일반 사용자에게 숨겨져 있었고 같은 `/record` 형식으로 갔습니다. 코드 참조도 남지 않았습니다. 요청 밖 변경으로 보지 않습니다.
- **주식 초안:** `stock_reflection`으로만 이어집니다. 제목이나 종목명이 없으면 기존 저장 검증에 막힙니다. 종목명 없이 제목만 넣으면 SAYU 목록에 `(종목 없음)`으로 표시되고 대시보드에서 빠집니다. 동작 한계이며 결함으로 보지 않습니다.
- **삭제 잔존:** HEAD 기준 검색에서 삭제 화면을 가리키는 코드는 없습니다. Rules 주석, 계정 삭제 테스트 주석, 회귀 테스트 안의 금지 목록만 남아 있습니다.
- **export:** 14개 제거와 추가 0을 독립 확인했습니다.
- **주식 OCR:** 함수 전체 확인 결과 구독·월간 한도 호출은 없고, `enforceRateLimit`만 있습니다. 1차에서 유보한 부분이 확정됐습니다.
