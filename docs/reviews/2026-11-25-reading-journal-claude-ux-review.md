- **홈에서 독서장으로 바로 가는 길이 없습니다.** 홈에는 "독서사유"만 있는 버튼이 없고, "어떤 내용을 남기고 싶으세요? … 9가지 형식과 설명 모두 보기 →" 안에 묶여 있습니다(error-home 스냅샷). 이번 diff의 범위는 아니지만, 첫 사용 경로에서 몇 번 눌러야 하는지 실측이 필요합니다.
- **같은 책이 두 권으로 갈라질 수 있습니다.** 처음에 저자 없이 쓰고, 나중에 SAYU를 거치지 않고 같은 제목에 "저자 추가 (선택)"를 채우면 서로 다른 책이 됩니다. `makeReadingBookId(title, author)` 때문이며, 테스트 `readingContinue.test.mjs:909-916`도 저자가 다르면 다른 책으로 취급합니다.
- **같은 대상을 부르는 이름이 섞여 있습니다.** 기록 / 회 / 회차 / 독서장 / 독서사유 / 완독이 함께 쓰이고, 04 화면에는 빈 입력칸 바로 옆에 "+ 오늘 소감 쓰기" 버튼이 또 있습니다.

## 유지할 장점

- 저자를 선택 항목으로 접어 두고 제목 + 한 줄만으로 저장되며, 저장 시 AI 다듬기 없이 원문을 그대로 저장합니다(diff 268-318행).
- SAYU의 "읽는 중인 책 · 기록 N개 · 이어 쓰기"는 새로고침 뒤에도 같은 책으로 이어집니다. 이어 쓸 때 오늘 칸은 비워 두고 이전 회차는 아래에 보여 줍니다(03·04 화면).
- "다 읽었어요"를 눌러도 AI가 자동으로 실행되지 않고 "(선택)"으로 열리며, 질문 없이 바로 완독 저장이 가능합니다. AI가 실패해도 저장할 수 있다는 안내 문구가 있습니다.
- 책 목록을 불러오는 중이거나 실패했을 때 `role="status"`/`alert`로 상태를 알려 줍니다.

## 최종 의견

- **독립 의견: 수정 후 승인.** 핵심 흐름은 요구사항대로 성립합니다. 다만 1번(완독 단계의 먹통 상태)과 2번(저장 직후 "기록 없음")은 첫 사용자가 실패로 오해할 확률이 높아서 출시 전에 고쳐야 합니다.
- **작업 규모: 소.** 1·2·4·5번은 문구, 조건식, 속성 정도의 수정입니다. 3번 원인이 데이터나 목록 로직 쪽으로 드러나면 중으로 올라갑니다.
- **운영 확인 범위**
  1. 실제 AI 응답 지연과 실패 상황에서 1번 흐름 확인 (asia-northeast3 리전)

  3. 기존 사용자의 예전 형식 독서 기록(readingBookId, final_reflection)이 "읽는 중인 책"과 완독 목록에 제대로 나뉘는지
  4. 07 단계를 다시 찍어 3번 확정
  5. 저자를 나중에 추가했을 때 책이 갈라지는지
