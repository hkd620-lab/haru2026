## 필수 수정

**1. 저장 중 겹침 확인 요청이 오면 '이미 저장됨' 거래가 '선택하지 않은 거래'로 바뀝니다**

해당 코드 (`FormatModal.tsx:2969-2971`):
```ts
if (error instanceof HouseholdDuplicateReviewRequired) {
  setHouseholdChecks(error.checks);   // 선택해서 보낸 행의 비교 결과만으로 전체를 교체
```
- 파일 저장에서는 선택한 행만 보냅니다 (`:2936`). 그래서 `error.checks`에는 처음부터 선택이 해제된 'already' 행의 비교 결과가 없습니다.
- 교체 후 생기는 일:
  - 미리보기에서 그 행들이 '중복 제외'에서 '선택하지 않은 거래'로 옮겨 갑니다.
  - 표의 '이미 저장됨' 표시가 사라집니다 (`:5299`).
  - 체크박스와 전체 선택이 다시 켜집니다 (`:2919`, `:2929`, `:5294`).
- 이 흐름은 자주 생깁니다. 겹침 선택이 남은 상태에서도 버튼이 눌리기 때문입니다.
- 데이터 손상은 없습니다. 저장 서비스가 이미 저장된 거래를 다시 'already'로 거릅니다. 다만 "선택 대기·미확인·미선택 구분"이라는 요구에 어긋납니다.
- 수정 예시: 교체하지 말고 id 기준으로 합칩니다.
```ts
setHouseholdChecks(prev => {
  const next = new Map(prev.map(c => [c.entry.id, c]));
  error.checks.forEach(c => next.set(c.entry.id, c));
  return [...next.values()];
});
```
수동 입력 경로(`:2782`)는 모든 행을 보내므로 그대로 둬도 됩니다.

**2. 확인 필요: 저장 경로를 거친 뒤 비교 기준(snapshot)이 계속 일치하는지**
- `snapshot`은 `Object.keys` 전체를 비교합니다 (`householdSavePreview.ts:9`).
- `saveHouseholdEntriesBatch`는 거래 목록을 `JSON.stringify(entries)`로 넘깁니다 (`:2751`).
- 만약 `onSave` 쪽에서 이 문자열을 다시 parse해 저장 서비스로 넘긴다면 문제가 생깁니다.
  - 값이 `undefined`인 키(`ocrSourceFile`, 선택 항목 같은 것)가 사라집니다.
  - 그러면 `error.checks[].entry`의 비교 기준이 화면의 `row.entry`와 영원히 어긋납니다.
  - 겹침 확인 요청 이후 모든 행이 '미확인'으로 굳고, 버튼이 계속 "중복 확인 후 저장"만 표시합니다. 수동 입력은 이 비교 결과가 유일한 출처라 영향이 큽니다.
- 범위 밖 파일이라 `onSave` 경로는 직접 읽지 않았고, 이 문제는 아직 확인되지 않았습니다.
- 현재 테스트는 비교 결과를 직접 넘기므로 이 경우를 잡지 못합니다.
- 간단한 방어책: snapshot에서 `undefined` 값을 빼는 것입니다.
  ```ts
  .filter(k => entry[k] !== undefined)
  ```
  아니면 `JSON.parse(JSON.stringify(entry))` 기준으로 비교합니다. 둘 중 하나를 적용하고, 실제 `onSave` 흐름으로 회귀 테스트 1건을 추가하길 권합니다.

## 비차단 권고
1. 저장 후 알림 문구(`신규 · 이미 저장됨 · 기존 거래 사용`)가 버튼의 "추가/중복 제외"와 다릅니다. 또 선택 해제된 'already' 행은 전송되지 않아 `result.already`에 들어가지 않습니다. 그래서 미리보기의 중복 제외 건수보다 알림 숫자가 작을 수 있습니다. 문구를 "추가 N건 · 중복 제외 M건"으로 맞추길 권합니다.
2. 파일을 불러온 상태에서는 수동 입력한 거래가 하단 버튼으로 저장되지 않습니다(요구대로입니다). 사용자가 모르게 넘어갈 수 있으니 안내 한 줄을 권합니다.
3. 선택 대기가 남아 있어도 버튼이 눌립니다. 서버가 막아 주므로 안전하지만, 겹침 확인 화면으로 바로 이동하는 동작이면 혼란이 줄어듭니다.
4. 미리보기 테스트에 다음 경우를 추가하길 권합니다.
   - 'already'인데 선택 해제된 행과 겹침 확인 요청이 동시에 있는 경우
   - 비교 결과가 `new`인데 이전 선택이 남아 있는 경우. 저장 서비스는 이를 `suspect`로 승격하지만(`:80`), 미리보기는 추가로 셉니다. 지금 흐름에서는 생기기 어렵습니다.
