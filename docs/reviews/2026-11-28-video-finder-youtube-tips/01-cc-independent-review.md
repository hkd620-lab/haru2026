### 판정 근거
변경 내용은 정적인 안내 영역 하나와 이미지 링크 2개뿐입니다.
```tsx
import youtubePhoneGuide from './assets/youtube-phone.png';
...
<a href={youtubePhoneGuide} target="_blank" rel="noopener" className="inline-flex min-h-11 ...">휴대폰용 그림 보기</a>
```
- **버그:** 찾지 못했습니다.
  - 이미지는 import로 불러오므로 빌드 때 해시가 붙은 파일로 나갑니다.
  - 독립 사이트 설정은 `vite.video-finder.config.ts:121`이 `assetsInlineLimit: 0`입니다. 그래서 이미지가 `data:` 주소로 바뀌지 않고, 새 탭으로 열 때 Chrome이 막지 않습니다.
  - HARU 쪽 PWA는 `navigateFallback: null`입니다(`vite.config.ts:86`). 새 탭에서 이미지 주소를 열 때 서비스 워커가 index.html로 바꿔치기하지 않습니다.
- **보안:** 같은 사이트 안의 이미지 링크라서 `rel="noopener"`만으로 충분합니다. 사용자 입력이 없고 외부 주소도, 저장 경로도, Functions도 건드리지 않습니다.
- **PNG 내용:** 개인정보는 보이지 않습니다. 두 이미지 모두 "메뉴 이름은 기기마다 다를 수 있어요"라는 단서가 있습니다. 안내 문구도 현재 유튜브의 한국어 화면 이름(내 페이지, 연속 재생, 현재 시간에 동영상 URL 복사 등)과 맞습니다.
- **작업 규모와 멈춤 조건:** 소규모 UI 추가입니다. 모델 변경, 라우터 변경, 커밋 메시지와 실제 변경의 불일치, 대규모 기능 중 어느 것에도 해당하지 않습니다.
- **검증 대조:** `gh pr view 459`로 실제 PR 상태를 확인했습니다. PR head가 검토 SHA와 같고, `build_and_preview`와 `Deploy Preview`가 모두 성공입니다. 양쪽 프런트 빌드, 17개 테스트, Chrome 375/1280px 화면 확인은 보고하신 결과를 근거로 삼았고 제가 다시 실행하지는 않았습니다.

### 병합을 막지 않는 개선 제안 (기장 전달용)
1. **접근성 (가장 중요):** 팁 8개와 4개의 내용이 그림 속 글자로만 들어 있습니다. 새 탭에서 PNG를 열면 대체 텍스트가 없어서 화면 낭독기 사용자는 내용을 전혀 알 수 없습니다(WCAG 1.1.1, 1.4.5). 다음 작업에서 같은 내용을 접을 수 있는 텍스트로 넣거나, 이미지를 담은 HTML 페이지로 바꾸고 alt를 붙이는 방법을 권합니다.
2. **새 탭 안내:** 문단에는 "새 탭에서" 열린다고 적혀 있지만, 링크 이름만 읽을 때는 그 사실이 전달되지 않습니다. 링크마다 `<span className="sr-only">(새 탭)</span>`를 붙이면 해결됩니다.
3. **회귀 테스트:** 이 영역에 대한 테스트가 없습니다. 기존 `videoFinder.policy.test.cjs`에 두 링크와 `target="_blank"`, `rel` 속성이 있는지 확인하는 정적 검사를 추가하면 좋습니다.
4. **그림 출처:** 컴퓨터용 그림 위쪽에 다른 사람이 올린 영상 화면(연주 장면) 일부가 보입니다. 위험은 낮지만, 다음에 그림을 고칠 때 이 부분을 흐리게 하거나 잘라내면 더 안전합니다.
