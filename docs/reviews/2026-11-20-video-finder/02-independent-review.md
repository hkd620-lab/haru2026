## 중점 점검

**탭 세션 보안: 문제 없음**
- 세션은 `sessionStorage`와 메모리에만 둡니다. 쿠키를 쓰지 않고(`credentials:'omit'`), 요청 본문에만 실어 보냅니다.
- 연결 창은 `postMessage` 대상 출처를 고정합니다. 받는 쪽은 출처·내가 연 팝업 창·요청 번호(nonce)를 모두 확인합니다.
- 독립 주소에는 X-Frame-Options DENY가 걸려 있습니다. 본 앱 연결 창을 iframe에 넣으면 `opener`가 없어 `noOpener` 상태로 끝납니다.
- 서버의 Origin 검사는 보조 수단일 뿐입니다. 브라우저 밖 도구로는 꾸밀 수 있어서, 실제 방어는 세션 토큰 자체가 합니다.
- 남는 위험: XSS가 생기면 최대 8시간, 이 기능의 데이터만 노출됩니다. HARU 기록과 결제는 범위 밖입니다.

**동의·계정 상태·로그아웃·만료: 문제 없음, 남는 점 2개**
- 요청마다 다음을 다시 확인합니다(`videoFinderCore.ts:615-638`).
  - Auth 정지·삭제
  - `tokensValidAfter`(토큰 취소 시각)
  - 비밀번호 계정의 이메일 미인증
  - 탈퇴 신청
  - 동의
- 탈퇴 처리가 세션 문서도 지웁니다.
- 남는 점 (낮음):
  - 본 앱에서 일반 로그아웃을 해도 `revokeRefreshTokens`를 부르지 않으면 독립 세션은 최대 8시간 남습니다. 화면에 "8시간 뒤 끝나요"라고 안내는 합니다.
  - 독립 주소에서 로그아웃해도 메모 임시본은 `localStorage`에 남습니다(키는 계정 해시). 공용 기기라면 로그아웃할 때 지우는 편이 낫습니다.

**레이스: 문제 없음**
- 담기·바꾸기·이력·세션 발급·할당량 쓰기가 모두 같은 트랜잭션에서 `users/{uid}`를 읽습니다.
- `requestAccountDeletion`과 `executeScheduledDeletion`의 `deletionStartedAt` 기록도 트랜잭션입니다(`accountDeletion.ts:68`, `:303-308`). 그래서 서로 순서가 정해지고, 삭제가 시작된 뒤에는 쓰기가 커밋되지 않습니다.
- 남는 점 (수용 가능): `deleteAll`은 잠금 없이 `recursiveDelete`합니다. 그래서 전체 삭제와 동시에 들어온 새 담기 1건은 살아남을 수 있습니다. 사용자가 직접 담은 것이라 받아들일 만합니다. 바꾸기와 최신화는 되살아나지 않습니다.

**색인·스케줄러: 배포 순서 주의 (중간, 운영)**
- 컬렉션 그룹 질의(`metaFetchedAt <`)용 fieldOverride를 넣었고, 기존 자동 색인 3종도 함께 적었습니다. 맞습니다.
- 다만 색인이 다 만들어지기 전에 스케줄러가 돌면 질의가 FAILED_PRECONDITION으로 실패합니다. 그러면 같은 함수 뒤쪽의 만료 세션 정리도 실행되지 않습니다.
- 그래서 `firestore:indexes`를 먼저 배포하고 생성이 끝난 것을 확인한 뒤 함수를 배포해야 합니다.

**Hosting 기본 주소와 운영 주소: 보안 문제는 없음, 미리보기 범위 제한**
- 서버의 CORS와 세션 대상 목록이 `https://youtube.haru2026.com` 하나로 고정돼 있습니다(`videoFinderCore.ts:32`). 그래서 다음 주소에서는 로그인할 수 없습니다.
  - `haru2026-video-finder.web.app`
  - 미리보기 채널 `--*.web.app`
- 빌드 환경값으로 연결 창의 허용 출처를 늘려도 서버가 거절합니다. 안전 쪽으로 닫혀 있는 구조입니다.
- 따라서 **미리보기에서는 정적 화면·CSP·로그인 첫 화면까지만 확인할 수 있습니다.** 로그인 이후 끝까지 확인하려면 커스텀 도메인을 연결한 뒤 해야 합니다.
- 연결 창은 `haru2026.com`으로 고정입니다. `haru2026-8abb8.web.app`에만 로그인한 사용자는 팝업에서 다시 로그인해야 합니다. OAuth 페이지를 거치면 `opener`가 끊길 수 있지만, `noOpener` 안내로 다시 시작할 수 있습니다.
- 본 앱 `firebase.json`에는 COOP 머리글이 없어서 `opener`를 막지 않습니다.
- 1차 검토의 "API 키 리퍼러에 youtube.haru2026.com 추가" 항목은 이제 필요 없습니다. 독립 묶음이 Firebase SDK를 쓰지 않기 때문입니다.

**scope 과잉 변경**
