## 수정 제안 요약

- **H1**:
  - `update`: `runTransaction`으로 문서를 읽고 바뀐 필드만 `tx.update`하세요. 문서가 없으면 `not-found`를 돌려줍니다.
  - `refreshStale`, `refreshMeta`, 정리 작업: `ref.update({ meta, metaFetchedAt, metaStatus })`처럼 영상 정보 필드만 바꾸세요. 문서가 지워졌으면 NOT_FOUND로 실패하고 되살리지 않습니다.
  - 이 경쟁 상황 시험을 추가하세요.
- **H2·M1 (한 번에 해결 가능)**:
  - `createCustomToken(uid, { vfStandalone: true })`로 표시를 붙이세요. 이 표시는 ID 토큰을 갱신해도 계속 들어 있습니다.
  - `requireActiveUid`에서 표시가 있는데 `standaloneSignIn`이 꺼져 있으면 거부하세요. 이렇게 하면 비상중지가 기존 세션에도 바로 적용됩니다.
  - 필요하면 다른 HARU 함수와 Rules에서도 이 표시를 보고 권한 범위를 좁힐 수 있습니다.
  - 독립 주소 CSP에 `script-src 'self'`를 넣고, 외부 폰트 출처만 `style-src`, `font-src`로 허용하세요.
  - "1회용" 설명은 "1시간 유효"로 고치세요.
- **M2**: 묶음 처리 대신 문서별로 실패를 견디게 하세요(`BulkWriter`, NOT_FOUND 무시). 기준을 27~28일로 당기고, 정리한 건수와 실패 건수를 기록해 경보를 붙이세요.
- **M3**: 운영 전에 `firebase target:apply`를 실행하세요. 한도 숫자와 다른 기능의 GCP 할당량 공유 여부는 대표님 결정이 필요합니다. 코드상 YouTube를 호출하는 곳은 이 기능뿐입니다.

## 확인된 안전 요소 (문제 없음)

- **UID**: `request.auth.uid`에서만 정합니다. 클라이언트가 보낸 `uid`는 무시하고, 계정 간 격리 시험도 있습니다.
- **Rules**: `rateLimits`는 클라이언트가 읽고 쓸 수 없습니다. 클라이언트가 자기 검색 횟수를 초기화할 수 없습니다. `config`, `videoFinderQuota`, `videoFinderSaved`, `videoFinderHistory`에는 허용 규칙이 없어 기본 거부되고, 최상위 와일드카드 규칙도 없습니다.
- **할당량**: 사용자 한도와 전체 한도를 한 트랜잭션에서 먼저 예약합니다. 설정 문서가 없으면 기능이 꺼진 상태(`enabled: false`)가 기본입니다.
- **YouTube 키**: Secret Manager로 관리하고 헤더로만 보냅니다. 로그에 키, 검색어, 메모가 남지 않습니다.
- **로그인 연결**: `postMessage` 대상 출처를 고정했고, 받는 쪽은 출처·팝업 창·nonce를 모두 확인합니다. 주소에 토큰을 넣지 않습니다.
- **리전**: 모든 함수가 `asia-northeast3`입니다.
- **경로**: `users/{uid}/records`는 건드리지 않았고 우회 컬렉션도 없습니다. 새 하위 컬렉션 `videoFinderSaved`, `videoFinderHistory`는 프로젝트 지침상 허대표님 경로 승인 대상입니다(코드 주석에도 명시).
- **탈퇴**: 두 하위 컬렉션이 탈퇴 삭제 목록과 시험에 들어갔습니다. 탈퇴 대기 중인 계정은 서버가 요청마다 차단합니다.
- **기능 분리**: '재미 영상'과 하단 탭은 그대로이고 비서실 '전체 보기'에만 추가됩니다. 유료 AI 호출 코드는 없습니다.
