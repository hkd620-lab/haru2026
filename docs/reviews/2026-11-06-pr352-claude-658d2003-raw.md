- **이전 계정 값**: 렌더 시점의 `authMatches`와 `state.uid === uid` 이중 확인으로 이전 계정 값이 나오지 않습니다.
- **날짜 정규화**: 서버 조회 범위는 문자열 비교로 나뉩니다. 따라서 한 자리 월(예: `2026-1-15`)은 다른 달 조회 범위에 들어오지 않습니다. 정규화 뒤에도 월초~오늘로 다시 거르므로 잘못 미래·과거로 분류되는 일이 없습니다. 오히려 기존에 미래로 잘못 빠지던 `2026-11-5`류를 바로잡습니다. 없는 날짜(2/30, 11/31)는 제외됩니다.
- **말줄임표 `…`**: 코드 포인트 20자를 초과할 때만 붙습니다. 정확히 20자면 그대로 둡니다. 이모지를 반으로 자르지 않습니다(테스트 확인).
- **live region**: 항상 마운트되는 `role="status"` span으로 옮겨졌습니다. `sr-only`는 Tailwind 4 유틸리티로 src 안에서 이미 쓰이고 있어 빌드에 포함됩니다.
- **SAYU 문서 경로**: `users/{user.uid}/records/{openRecordId}`로 로그인한 본인 기준입니다. SayuPage에 다른 사용자의 기록을 여는 화면은 없습니다.
- **SAYU 늦은 응답 무시**: 취소 플래그와 `currentRecordsUidRef` 확인이 실제로 동작합니다. 문서가 없거나 오류이면 안내 후 이동 상태를 해제합니다.
- **SAYU 열기 흐름**: `openFormatSayu`는 단건 레코드만 쓰고 전체 목록에 의존하지 않습니다. 따라서 단건만 먼저 넣고 열어도 회귀가 없습니다. 이후 전체 목록이 덮어써도 그 목록에 같은 문서가 들어 있습니다.
- **환불 닫기 3경로**: 직전 화면 `/settings → /refund → /settings`, 직전 `/`, 직접 방문 `/refund → /` 모두 통과했습니다. react-router 8.5.1에서 첫 진입 시 `location.key`가 'default'인 것을 소스에서 확인했습니다.
- **OG 메타**: `og:type`, `og:site_name`, `og:locale` 3줄 추가만 있습니다. og:image와 공유 이미지 정책 테스트를 통과했고, `public/welcome`의 기존 메타와도 충돌하지 않습니다.
- **홈 추천**: 기존 필터에 라벨 1개만 추가했습니다. 이미 내 비서인 경우는 `!homeAgents.includes`로 중복 추천을 막습니다. 저장·쓰기 변경은 없습니다.
- **문구 숫자**: "14가지 AI 비서"는 `homeAssistantDescriptions.ts`의 14개 항목과 일치합니다. "11가지"는 랜딩의 기존 "11가지로 시작합니다"와 일치합니다.
- **범위**: `git diff --stat` 기준 Rules·인덱스·Functions·`firebase.json`·CI 변경이 0입니다. 추가된 코드에 Firestore 쓰기나 AI 호출이 없습니다. `users/{uid}/records` 경로가 유지됩니다.
- **검사 도구 격리**: `test/month-progress-browser/`는 운영 번들에 섞이지 않습니다.
  - vite 입력은 index.html뿐이고, Tailwind 스캔 범위(`@source '../**/*'`)는 src 안으로 한정됩니다. Hosting 배포 폴더는 `frontend/dist`입니다.
  - 빌드한 dist를 검색해 도구 문자열이 없음을 확인했습니다.
  - 도구 안의 firebase 스텁은 순수 가짜 객체입니다. 실제 키·프로젝트를 쓰지 않습니다.
- **`devConsoleCleanup.test.mjs` 수정**: 항상 통과하도록 바뀐 것이 아닙니다. 실제 홈 클릭 핸들러를 뽑아 11종 × 4가지 경우로 실행하고 전달값을 비교합니다. 예전 단언은 현재 코드 구조와 맞지 않아 실패하던 것이고, 새 단언이 같은 의도를 더 정확하게 검사합니다.
