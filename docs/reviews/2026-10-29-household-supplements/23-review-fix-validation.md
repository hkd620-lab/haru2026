## 최종 브라우저 확인

코드 고정 뒤 **새 Vite 프로세스/포트18770**을 실행하여 이전 개발 중 서버 결과와 구분했다. 합성 자료만 사용하고 실제 운영으로 연결하지 않는 하네스다. Chrome viewport를 375×812로 설정했고 스크롤바를 뺀 document clientWidth와 scrollWidth가 모두 360px로 가로 넘침이 없었다. 임시 viewport는 검증 후 reset했다. 아이폰 실기기 E2E는 아니다.

1. 명시 체크로 합성 거래처 `합성 기억 검증`의 교통비 규칙을 현금 저장과 함께 만들고, 쓰기 2회(거래1+규칙1)를 확인.
2. 교통비 분류를 보관하고 보관됨/보관 해제/기존 거래 수 유지 확인. 새 현금 입력에서 같은 거래처를 입력해도 **분류 선택 상태, 기억 안내 0개**로 제안이 차단됨을 확인. 규칙·과거 거래를 삭제하지 않음.
3. 분류 관리에 초안을 입력한 뒤 즉시 other 계정 전환. 열린 dialog 0, 이전 초안 입력 필드 0으로 이전 입력과 관리창이 사라짐.
4. `legacy-array` 합성 시나리오(3건)에서 id 없는 두 동일 거래처·날짜·금액 행 중 선택한 행만 식비로 저장됨. 나머지는 기타, 전체3건 유지. 선택 행에 원래 CRLF 메모 `예전 메모 첫 줄\r\n예전 메모 둘째 줄`이 그대로 표시됨.
5. [현금 입력 최종 화면](22-browser-final-cash.png)은 합성 검증이며, 화면용 입력만 채운 상태를 촬영했다. 이 촬영 시도는 거래 저장을 누르지 않았다. 이전 현금 저장/응답 유실 재시도 증거는 11 기록과 SDK 회귀가 뒷받침한다.
