# 가계부 후속 범위 변경 — 파일 가져오기 중심

> 은행·카드 API 자동연동은 추진하지 않고, 거래내역 파일을 쉽게 내려받아 하루 가계부에 가져오는 방향으로 정리
> 은행·카드별 다운로드 안내와 PDF·엑셀 가져오기, 중복 방지를 편하게 만드는 데 집중하자

## 이전 장부와의 관계

- 이 결정은 HANDOFF.md와 NEXT_HANDOFF.md의 9번 ‘은행·카드 자동 연동’ 추진 계획을 대체한다. API 자동연동은 보류 과제가 아니라 현재 추진 범위에서 제외한다. 공급자·계약·요금 조사, 금융기관 API 연결 구현을 진행하지 않는다.
- 4번 ‘카드 내역 가져오기 + 은행 내역 연결’은 파일로 가져온 거래의 연결과 중복 합산 방지를 뜻한다. 은행·카드 API 연결을 뜻하지 않는다.
- 현금 입력·분류·수정 등 이미 배포한 기능은 유지한다. 고정지출·할부·배분·잔액·목표·가족 조회 공유는 기존 잔여 장부에 유지하되, 이번 우선 작업은 아래 파일 가져오기 흐름이다.
- 이전 검토·인수인계 원문과 미커밋 NEXT_HANDOFF.md는 보존한다. 이 문서는 범위 결정 기록이며 구현·검토·배포 완료 근거가 아니다.

## 우선 작업과 완료 기준

1. **은행·카드별 다운로드 안내**: 공식 안내를 확인해 앱/웹의 다운로드 위치, 기간 선택, 지원 파일 형식, 암호 처리와 모바일에서 파일을 선택하는 방법을 안내한다. 확인한 기관·형식만 지원한다고 표시한다. 안내에는 확인일과 공식 근거를 남긴다.
2. **PDF·엑셀 가져오기**: 파일 선택 → 읽기 → 날짜·사용처·금액·유형·분류 미리보기 → 사용자 확인 → 저장 흐름을 쉽게 만든다. 현재 파서 재사용 가능성을 먼저 확인하고, 읽을 수 없는 형식·스캔 PDF·암호·누락 행은 구체적으로 안내한다. 실패한 자료를 성공한 거래처럼 저장하지 않는다. 범용 열 매핑은 실제 형식 확인 후 필요한 범위로 설계한다.
3. **중복 방지**: 같은 파일 재가져오기, 기간이 겹치는 다른 파일, PDF와 엑셀의 같은 거래를 확인한다. 은행 카드대금과 카드 개별 내역, 체크카드 양쪽 내역의 이중 합산도 별도로 검증한다. 날짜·금액만 같은 정상 반복 거래를 임의로 제거하지 않는다. 불확실한 연결은 사용자 확인을 받는다.
4. **기존 데이터 보존**: 기존 거래·메모·분류·원본 식별 키를 보존한다. 과거 529건을 자동 재분류하거나 운영 데이터를 일괄 변경하지 않는다. 합성 자료로 먼저 검증한다.

## 현재 코드 확인 범위

- 가계부는 `householdKakaoImport.ts`와 `householdKakaoPdfImport.ts`를 통해 카카오뱅크 PDF/XLSX를 읽는 경로가 있다.
- `FormatModal.tsx`의 HARU보조장부에는 국민카드 XLS/XLSX 가져오기 경로가 별도로 있다. 이를 가계부 지원 완료로 간주하지 않으며, 재사용 가능성과 거래 의미·저장 방식 차이를 먼저 검토한다.
- 이 확인만으로 다른 은행·카드, 모든 PDF·엑셀, 기관 간 중복 연결을 지원한다고 주장하지 않는다.
