# 가계부 보완사항 구현 인수인계

## 현재 판정

**❌ 보완 기능 구현 미착수 / 요구사항 반영 및 인수인계 작성.** 이전 조회 대시보드 배포는 완료했지만, 이번 보완 기능을 완료했다고 보고하지 않는다. AGENTS.md 14절의 독립 작업 전환·맥락 누적 기준에 따라 새 대화로 넘긴다. 재승인을 요구하지 말고, 아래 승인 범위의 독립 구현을 이어간다.

## 사용자 승인과 의도

- 최신 직접 지시: **“확인한 보충사항을 반영바람”**.
- 대부분의 지출은 카드 거래. 은행/카드 자료로 대부분을 기록하고 빠진 현금 거래를 간단히 보충한다.
- 현금 전용 입력: 오늘 날짜 기본, 금액, 지출 기본/현금 수입 선택, 사용처 또는 받은 곳, 카테고리 선택·직접 입력, 선택 메모. 결제수단은 내부적으로 현금. 이 화면에 사진/영수증, 은행 파일 선택, 이체, 결제수단 선택, 테스트 데이터 버튼을 노출하지 않는다.
- 은행 거래는 수입·지출·이체 각각 카테고리를 선택하거나 직접 만든다. 직접 만든 분류를 재사용하고, 이미 저장한 거래의 카테고리·메모 수정과 여러 거래 일괄 분류를 지원한다. 수정 내용은 재가져오기에도 보존한다.
- 기록·구분·검색·통계·비교의 용도가 명확하고, 모바일에서도 읽고 누르기 쉬운 고급스러운 화면을 원한다.
- 기존 지시: **기존 529건과 메모 보존, 검증·코드 검토 후 PR 생성, 이상 없으면 main 병합과 Hosting 운영 배포까지 진행**. 기존 승인은 계속 유효하며 반복 확인하지 않는다. 다만 새 외부 계약/비용, 권한 확대, 운영 데이터 일괄 수정 등 별도 대상이 필요한 행위까지 임의로 확대하지 않는다.

## 승인된 보완사항 전체 목록

앞서 비교한 항목 전체가 작업 장부에 남아야 한다. 일부만 구현하고 전체 완료로 보고하지 않는다. 구현/검토/배포를 작은 단위로 나눌 수 있으나, 다음 항목의 남은 상태를 계속 이어간다.

| 순서 | 보완사항 | 완료 기준·주요 조건 |
|---|---|---|
| 1 | 현금 전용 간편 입력 | 위 현금 전용 구성. 입력 전 빈 행을 ‘거래 1건·중복 확인 필요 1건’으로 표시하지 않음. 기존 중복 확인·저장 트랜잭션 재사용, 정상 반복 거래 보존. 은행 가져오기 버튼과 실제 진입 화면 구분. |
| 2 | 카테고리 선택/직접 입력/재사용·세부 분류 | 수입/지출/이체별 분류. 저장 후 수정·일괄 지정. 사용자 분류와 메모·원본 식별 키를 재가져오기가 덮어쓰지 않음. 미분류 모아 확인. |
| 3 | 거래처별 분류 기억 | 사용자가 정한 규칙을 다음 거래의 제안으로 적용. 일회성 예외 분류를 무조건 이후 전체 거래에 덮어쓰지 않음. 과거 529건을 자동 일괄 수정하지 않음. 신규 AI 호출 없이 가능한 명시 규칙부터 검토. |
| 4 | 카드 사용내역 가져오기 + 은행 내역 연결 | 은행 명세서의 카드대금 합계만으로 개별 식비/쇼핑을 알 수 없다는 한계를 반영. 개별 카드 사용내역 지원과, 통장 카드대금·카드 승인 내역을 이중 지출로 합산하지 않는 연결 필요. 같은 파일 중복 차단과 별개. 체크카드 은행/카드 양쪽의 같은 거래도 검토. |
| 5 | 반복 거래·고정지출·할부 | 예정과 실제 거래를 구분. 은행 자료와 예정 거래가 함께 들어와 중복 저장되지 않음. 원구매·할부 청구의 집계 기준을 명시하고 남은 횟수·금액 확인. |
| 6 | 한 거래 여러 카테고리 배분 | 배분 금액 합계가 원거래 금액과 일치. 원거래/배분을 동시에 합계에 더하지 않음. 원본 식별 키·총금액 보존. |
| 7 | 실제 잔액 맞춰보기 | 계좌별 기초잔액/기간/연결 거래 기준을 명확히 함. ‘수입−지출’과 실제 잔액을 혼동하지 않음. 부족한 정보가 있으면 잔액 일치를 완료로 주장하지 않음. |
| 8 | 저축 목표·가족 공동 관리 | 현재 월 예산과 저축 목표를 구분. 공동 관리는 대상 사용자·권한·초대/해제·노출 범위를 먼저 구체화. 다른 사용자에게 기존 기록을 자동 공개하지 않음. |
| 9 | 은행·카드 자동 연동 | 파일 가져오기와 실제 자동 연동을 구분. 공급자/지원 금융기관/계약·비용/인증·동의 조건 조사 필요. 계약·자격증명 없이 완료할 수 없음. 동작하지 않는 연결 버튼을 완료 기능처럼 배포하지 않음. |

행 8은 이전 비교표의 ‘저축 목표·가족 공동 관리’를 나누어 구현할 수 있고, 전체는 이전 비교표 8개 기능 및 이후 합의된 현금 입력·카테고리 요구를 모두 포함한다. 우선순위는 **현금·카테고리 → 카드 내역/이중 계산 방지 → 분류 기억/일괄 수정 → 고정지출·할부/배분/잔액·목표 → 공동 관리/자동 연동의 필요한 조건 해결**. 후순위도 요청 범위에서 누락하지 않는다.

## 미확정 입력·외부 의존성

- 카드사·지원할 명세서 형식이 아직 정해지지 않았다. 기존 카드 파서를 실제 가계부에 재사용할 수 있는지 먼저 확인한다. 지원 근거 없는 ‘모든 카드사 지원’ 주장은 금지. 범용 열 매핑과 합성 샘플로 구현 가능한 범위는 먼저 진행하고, 정확한 형식/카드사 정보가 꼭 필요할 때만 간결하게 질문한다.
- 자동 연동 공급자·계약·요금·인증정보는 제공되지 않았다. 기존 연결/비밀값을 임의 탐색·노출하지 않는다. 조사 후 구체적인 선택·비용·권한 조건을 사용자에게 제시한다. 계약/결제/새 보안 권한은 적절한 시점에 별도 확인한다.
- 가족 공유 대상 계정과 권한도 미지정이다. 개인 가계부를 공개·공유로 자동 전환하지 않는다. Rules/인증 정책 변경이 필요하면 정책 8.1의 해당 절차를 따른다.
- 실제 잔액 대조를 위한 기초잔액과 계좌 구분이 미확정이다. 데이터가 부족한데 정상 잔액으로 단정하지 않는다.
