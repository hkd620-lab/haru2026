## 구현 결과

카카오뱅크 텍스트 PDF·XLSX 선택 → 미리보기·분류 수정 → 중복 비교 → 원자 저장. 명확한 재가져오기는 제외하고, 다른 출처의 같은 날짜·금액은 사용자의 선택을 요구한다. 정상 반복 행과 기존 거래·메모·다른 형식을 보존하며 기존 중복을 자동 삭제하지 않는다. 상세 원본의 동시 덮어쓰기와 일반 호출자 콜백의 중복 검사 우회를 차단했다.

PDF·암호 없는 XLSX는 기기 안에서 읽으며 PDF 원본·암호를 서버에 보내지 않는다. 암호 있는 XLSX만 기존 decryptKakaoXlsx를 사용한다. 계좌·조회 원문은 저장하지 않고 해시에만 포함한다. 스캔 PDF·타 은행 임의 양식·XLS/CSV는 지원하지 않는다.

## 대표님 결정 및 다음 첫 행동

독립 검토에서 규모 대·8.1 멈춤 조건 해당을 확인했다. 다음을 승인받기 전 main 병합·운영 배포하지 않는다.

1. 월별 고정 문서 ID YYYY-MM-01_household 및 월 1일 대표 날짜. 당일 환경 정보는 월 문서에 붙이지 않는다. 기존 문서는 이동하지 않는다.
2. 기존 문서에 제외 확인 키 household_importKeys 메타데이터를 추가하는 방식. 기존 거래 필드는 보존한다.
3. 미리보기와 저장 때 각각 기록 컬렉션 전체를 읽는 비용·지연과 오프라인 저장 제한. 전체 읽기는 약 2N이며 재확인 읽기는 별도다.

다음 첫 행동은 허대표님의 위 방식/병합·배포 승인 범위를 확인하고 최종 PR HEAD·CI·코드 검토 대상과 기록 추가 전용 diff를 다시 확인하는 것이다. 승인 시 Hosting 자동 배포를 사용하고 실제 운영 E2E를 별도로 확인한다. Functions·Rules 수동 배포는 필요하지 않다.

## 남은 비차단 확인

- 동일 기간을 다시 발급한 PDF는 발급일시 등이 달라 의심으로 보일 수 있다. 같은 파일의 이름 변경 재가져오기는 이미 검증했다.
- 예금주 콜론 분리·영문 띄어쓰기 등 다른 PDF 레이아웃은 본인 이체 분류를 미리보기에서 확인해야 한다.
- 운영 암호 XLSX 해제·실제 모바일·운영 이용 이벤트 전송은 로컬 fixture로 완료 주장하지 않는다.
- 원본 저장 오류는 금융 자료 노출 방지를 위해 예외 원문을 로그로 남기지 않는다.
- 금융 원본과 실전 자료는 저장소/PR/Slack에 포함하지 않는다. 금지 파일·숨김 페이지를 복구·점검·수정하지 않는다.
