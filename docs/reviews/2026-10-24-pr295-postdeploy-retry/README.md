## 실제 소스 함수에 오류를 주입한 격리 검증

운영 데이터·네트워크·Rules를 바꾸지 않고, 실제 RecordPage.handleSaveFormatData와 FormatModal.handleSaveOriginalAsSayu 본문을 읽어 transpile하여 연결했다. Firestore 경계만 메모리 저장소로 대체했다. 통계는 두 페이지의 실제 로딩 effect를 실행했다. 운영 UI E2E와 구분한다.

- 저장 전 거절: 오류 안내, saving=false 복구, 입력 원문·초안 유지, 성공 탐색/초안종료 없음. 다음 저장 성공, 동일 ID·날짜·원문 SAYU 유지, 저장소1건, 성공 시 초안 종료 및 /sayu 탐색.
- 저장 완료 후 응답 유실: 첫 요청을 저장한 뒤 오류 반환. 재시도에서 같은 ID 기존 문서를 조회·merge하여 저장소1건 유지. 동일 원문 보존·성공 탐색. 중복 생성 없음.
- 통계 첫 화면: 조회 reject 시 loadFailed=true·records=null로 유지. 다음 effect 실행에서 오류를 지우고 기록 복구.
- 형식 상세: 같은 reject→복구 동작 통과. 두 경로 모두 throwOnError=true 전달 확인.
- 실행: 저장소 루트에서 `node docs/reviews/2026-10-24-pr295-postdeploy-retry/retry-probe.cjs`. 외부 통신 없음. 결과4개 모두 PASS: probe-result.txt.
- 기존 관련 회귀 테스트13/13 통과: writeBeforeFormat, writingDraftLifecycle, statsPeriodUrl, mergePeriodAccess. 제품 소스 변경이 없으므로 이전 통과한 전체 빌드를 반복하지 않음.
