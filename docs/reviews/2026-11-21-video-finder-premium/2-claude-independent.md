## 요청 항목별 결론

### 1. 실패 포함 공급자 한도 — 해소됨, P2 1건
- `planQuestionReservation`이 `provider { attempts+1, seconds+needSeconds }`를 lease와 **같은 트랜잭션에서** 늘립니다. 실패·시간 초과·예약 만료 때 `release`는 provider를 건드리지 않습니다.
- 하루 15회, 구독 기간 10,800초 상한이 실패를 포함해 지켜집니다. 사전 확인 단계에서도 상한을 걸러 YouTube 호출 전에 막습니다.
- 날짜·기간 키를 따로 초기화하는 로직(`providerUsed`)도 맞습니다.
- **P2-1:** 120분 영상이 한 번 시간 초과로 실패하면 공급자 분석 시간 7,200초가 그대로 빠집니다. 남은 3,600초로는 그 기간 동안 60분이 넘는 영상을 분석할 수 없습니다.
  - 75초 안에 2시간 영상 답이 오는지는 실측되지 않았습니다.
  - 실측 전까지는 `MAX_ANALYSIS_VIDEO_SECONDS`를 30~60분으로 낮추길 권합니다.
- **P2-2:** `thinkingConfig: { thinkingLevel: 'MINIMAL' }`이 대상 모델에서 받아들여지는 값인지 실측이 필요합니다.
  - 거부되면 모든 호출이 400으로 실패합니다. 그때마다 시도 횟수만 깎여 기능 전체가 멈춥니다.

### 2. Firestore 병합·동시성 — 대체로 양호, P1 1건
- 동의 쓰기의 merge는 확인됩니다. 에뮬레이터 테스트가 `acceptPolicy` 뒤 `acceptAiConsent`가 `aiConsentAccepted === true`임을 확인하는데, 이 값은 일반 동의가 남아 있어야 참이 됩니다.
- 반대 순서는 테스트되지 않았습니다. AI 동의 뒤 `acceptPolicy`를 다시 실행했을 때(버전 상향 포함) set이면 AI 동의가 지워집니다. 실패 시 닫히는 방향이라 P2입니다.
- **P1-1 (확인 필요): `deleteAll`이 usage 문서를 지우거나 merge 없이 덮어쓰는지**
  - **재현:** 질문 15회 실패 → 보관함 전체 삭제 → 다시 질문. 이때 `provider`·`dayCount`가 0으로 돌아가면 비용 상한을 계속 우회할 수 있습니다.
  - **경로:** `videoFinderStore.ts`의 deleteAll 쓰기(dataEpoch 증가 부분)
  - **조치:** `provider`·`dayCount`·`monthSeconds`가 전체 삭제 뒤에도 남는지 에뮬레이터 테스트 1건을 추가합니다.
- 이전 답변(`previousAnswers`)은 트랜잭션 밖 사전 읽기에서만 읽습니다.
  - 그 사이에 전체 삭제가 일어나면, 지운 대화가 한 번 Gemini로 갈 수 있습니다.
  - 저장은 epoch 확인으로 막힙니다. 낮은 등급(P2)입니다.

### 3. 지불 상태·endDate·갱신 — 1차 M1은 해소, P2 1건과 확인 1건
- 만료일 없는 `active`를 거부하는 것은 맞습니다(실패 시 닫힘).
- **P2-3 (1차 L2가 남음):** `pay:` 키에 `nowMs - lastPaid < 32일` 조건이 있습니다.
  - **재현:** `lastPaidAt=D`, 운영에서 `endDate`를 D+50일로 연장. 33일째부터 키가 `m:YYYY-MM`로 바뀌어 사용자 7,200초와 공급자 10,800초가 새로 생깁니다.
  - **수정:** `lastPaid ≤ now < end`이고 `end - lastPaid ≤ 62일`이면 그 기간 내내 `pay:lastPaid`를 쓰도록 32일 조건을 없앱니다.
- **확인 필요:** 실제 결제 갱신 코드가 `lastPaidAt`을 쓰는지, 그 값이 `toEpochMs`가 읽는 타입(Timestamp 또는 ISO)인지 확인해야 합니다.
  - 타입이 맞지 않으면 `null`이 되어, 결제한 프리미엄 사용자도 전원 거절됩니다.
  - 다른 프리미엄 기능과 판정 결과가 같은지(`cancelled`를 만료일까지 허용하는지 등)도 팩트시트와 대조해야 합니다.

### 4. 일반·AI 분리 동의 — 구조는 맞음, P1 1건
- AI 동의는 서버 스위치·프리미엄·일반 동의를 모두 마친 뒤에만 받습니다.
- 질문의 사전 확인·예약·확정 세 단계 모두 `assertBothConsents`를 거칩니다.
- **P1-2: AI 동의 철회 경로가 없습니다.**
  - `handle`에 철회 action이 없고, 전체 삭제를 해도 동의 기록은 남습니다.
  - 개인정보 국외 이전 동의는 철회할 수 있어야 하므로, `questionsEnabled`를 켜기 전에 철회 action과 화면 버튼을 추가해야 합니다.
- **확인 필요:**
  - 일반 동의 화면의 `VideoFinderPolicySummary`(diff에 없음)에 여전히 Gemini 전송 동의 문구가 섞여 있는지 확인해야 합니다.
  - 처리방침 시행일이 갱신됐는지 확인해야 합니다(diff상 변경 없음).
  - 국외 이전 고지에 받는 자를 「Google LLC」로 명시하고 문의처를 적었는지 확인해야 합니다.

### 5. 구형 클라이언트·배포 순서 — 해소됨
- `policyRequired`는 기본 꺼짐이고, Functions → 두 사이트 → 스위치 켜기 순서가 주석과 테스트에 반영돼 있습니다.
- `questionsEnabled`가 꺼져 있는 동안에는 9eb86d54 시점의 클라이언트가 보내는 `previous`도 버려지거나 거절됩니다.
- 남은 것은 "프론트가 Functions보다 먼저 배포되면 오류 화면"이라는 순서 제약 하나입니다. 배포 절차서에 적으면 됩니다.

### 6. 서버가 신뢰하는 이전 질문·근거 시각 — 해소됨, P2 1건
- 이전 대화는 같은 uid·같은 videoId·만료 전인 `answer_{id}` 기록만 씁니다. 질문 원문도 서버가 검증한 값을 저장합니다. 클라이언트가 지어낸 대화는 들어갈 수 없습니다.
- 요약 노트 기반 답변의 시각은 노트에 있는 시각과 정확히 같을 때만 남습니다(실패 시 닫힘).
- 영상 분석 답변의 시각은 범위만 확인하는데, 이는 구조상 한계입니다.
- **P2-4:** 답변 기록 TTL이 1시간입니다.
  - **재현:** 1시간이 지난 뒤 같은 창에서 후속 질문. 화면에는 이전 대화가 보이지만, 모델은 이전 대화 없이 답합니다.
  - **수정:** TTL을 요약 TTL(18시간)에 맞추거나, 이전 대화가 빠졌다는 안내를 표시합니다.

### 7. 보관함 보존 — P1 1건 (확인 필요)
- 동의 전 화면에 백업 버튼이 생겼고, 서버 허용 목록에 `'backup'`이 추가됐습니다.
- **P1-3:** 에뮬레이터 테스트는 `requirePolicyFor(uid,'library',{action:'backup'})`만 확인합니다. `client.downloadBackup()`이 실제로 `action:'backup'`을 보내는지는 확인하지 않습니다(`videoFinderApi.ts`·`standaloneClient.ts`가 diff에 없음).
  - **재현:** `policyRequired=true`, 동의하지 않은 계정에서 「기존 영상 찾기 자료 백업」 클릭. action 이름이 `export` 등으로 다르면 `failed-precondition`이 나고, 사용자에게는 삭제만 남습니다.
  - **조치:** 두 클라이언트의 action 이름을 대조합니다. 동의하지 않은 상태에서 백업이 성공하는 통합 테스트를 추가합니다.

### 8. Rules — P1 1건 (1차 H2가 일부만 해소)
- **P1-4:** 추가된 테스트는 `subscription/info` 쓰기 거부뿐입니다. 아래 경로는 클라이언트 읽기·쓰기 거부 테스트가 보이지 않습니다.

- 특히 usage(provider 카운터)에 쓸 수 있으면 비용 상한이 무력화됩니다.
- 기존 반복문 목록에 이 경로들이 이미 있다면 해소입니다. 확인이 필요합니다.
