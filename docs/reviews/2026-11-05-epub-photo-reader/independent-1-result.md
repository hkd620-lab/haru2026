**수정 후 승인**

"수정 후 승인"이라고 판정한 이유는 코드 결함이 아니라 운영 반영 전 근거 두 가지가 비어 있기 때문입니다. 하나는 8.1절 판정①이 요구하는 원문 로그와 export 목록 비교이고, 다른 하나는 최종 파일의 갤럭시 재검증입니다. 코드를 다시 고칠 차단 사항은 없습니다. 검토는 Read/Grep만 사용했고 테스트와 빌드를 제가 직접 실행하지는 않았습니다.

## 확인 항목별 판단

**1. html/body column 강제 제거 — 방향 맞음**
- 원래 코드는 `body,html{column-count:1!important;columns:1!important;column-width:auto!important}*{column-count:unset!important}`로 리더의 단 설정을 덮어쓰고 있었습니다. Play 북 같은 리더는 이 단 설정으로 페이지를 나눕니다. 이를 덮어쓰면 "넘김 막힘 + 내용이 옆으로 밀려 조각만 보임"이 생길 수 있어, 증상 설명과 맞습니다.
- 사용자가 알려 준 갤럭시 A/B(CSS만 바꾼 파일에서 사진과 페이지 이동 정상)도 같은 방향을 가리킵니다. 다만 이 결과는 구두 정보이고, 저장소에 원문 화면이나 로그가 없습니다.
- 라이브러리 확인: `epub-gen-memory`는 `css` 옵션을 `style.css`에 그대로 씁니다(`dist/lib/index.js:149`). 기본 템플릿 CSS는 이전에도 쓰이지 않았으므로, 이번 변경으로 없어지는 기본 스타일은 없습니다.

**2. 긴 세로 사진의 비율과 잘림**
- `max-width:100%` + `max-height:95vh` + `height:auto` 조합이면 CSS 규칙상 가로세로 비율이 유지됩니다.
- 인라인 style에는 max-height가 없어서 스타일시트 값과 충돌하지 않습니다.
- 위험(비차단): 리더마다 `vh` 기준이 다릅니다. 기준이 화면이 아니라 여백 포함 영역이면 95vh가 실제 페이지보다 클 수 있습니다. 그러면 `break-inside:avoid`와 겹쳐 사진이 다음 쪽으로 밀리거나 아래가 잘릴 수 있습니다. 실기기에서 긴 세로 사진으로 확인해야 합니다.

**3. 단건·합본 모두 적용됨**
- 실제 사진이 들어가는 곳은 `buildAndSave` 한 곳입니다(`functions/src/epubExport.ts:278`). 이 함수가 단건·기간·recordIds 요청을 모두 처리합니다.
- `mergeRecordToHtml`은 `[]`로만 호출돼(`epubExport.ts:206`) 실제 사진 경로가 아니지만, 같은 함수로 맞춰 둔 것은 문제없습니다.
- 회귀 테스트도 단건(`singleRecordId`)과 `recordIds` 두 경우를 각각 실제 EPUB으로 만들어 압축을 풀어 확인합니다.

**4. 공통 설치 안내 — 적절함**
- 4개 진입점(SayuModal, MergeViewer, SayuTogether, RecordBook) 모두 `exportRecordsToEpub` → `confirmEpubExport`(`epubExportService.ts:34`)를 거치므로 안내창이 공통으로 뜹니다.
- 보조패널 `EpubReaderNotice`는 3곳(MergeViewer:866, SayuTogether:1029, RecordBook:617)에 있습니다. SayuModal은 기존처럼 완료 알림 한 줄 안내만 있습니다. 이번에 바뀐 구조가 아닙니다.
- 계정 업로드 설명(`note`)과 설치 링크는 Android에만 표시되고, iOS·desktop에는 나오지 않습니다(테스트로 확인).
- 설치 URL은 기존 그대로이고, `target=_blank`, `noopener` 설정도 유지됩니다.
- 취소·ESC·close는 모두 false를 돌려주고, 중복 창 방지도 그대로입니다(`epubExportGuide.ts:5, 86-89`).
- 요구된 순서(설치 → 하루 복귀 → 휴대폰 직접 다운로드 → 내 파일에서 Play 북 → 라이브러리)와 계정 업로드 설명이 모두 들어 있습니다.

**5. auth/Storage/Firestore/리전/exports/비용 — 변경 없음**
- diff에 인증, Storage 경로(`epub/${uid}/…`), Firestore 조회, 리전, `index.ts`가 포함되지 않았습니다.
- 새로 export한 `EPUB_STYLESHEET`와 `epubPhotoHtml`은 모듈 내부용입니다. `index.ts`는 `exportEpub`만 다시 내보내므로(`index.ts:12885`) Cloud Functions 목록은 바뀌지 않습니다.
- AI 호출이나 비용 변화도 없습니다.

**6. 테스트·빌드 검증 범위**
- 새 테스트는 의미가 있습니다. 실제 EPUB의 `style.css`에 column, html, body, `*` 규칙이 없는지와 사진 2장이 내장됐는지를 봅니다. 수정 전 코드라면 실패하는 조건입니다.
- 한계: 1×1 PNG라서 실제 배치(잘림, 세로 사진)는 검증하지 못합니다. 이 부분은 실기기에서만 확인할 수 있습니다.
- 시험 결과는 구현자 요약뿐입니다(functions 18/18, frontend 11/11, 빌드 2개 통과). 명령 원문 출력이 없습니다.
- 프런트 빌드는 시험용 env 값으로 했습니다. 실제 환경 빌드는 PR CI 결과로 대신 확인해야 합니다.

**7. 작업 규모·8.1 멈춤 조건**
- 중규모로 봅니다(Functions 출력 레이아웃 + 안내 문구).
- 멈춤 조건 중 모델 변경, 커밋 메시지 불일치(메시지와 내용 일치), 경로·Rules·결제·인증·비용 변경은 해당하지 않습니다.
- 다만 "실기기 운영 E2E가 완료 조건인 작업의 운영 완료 판정"은 멈춤 조건에 해당합니다. 운영 완료는 허대표님이 확인해야 합니다.
