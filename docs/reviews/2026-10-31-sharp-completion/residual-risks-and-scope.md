# 남은 위험과 승인 범위 기록 — PR #319 (sharp 0.35.5)

기존 README와 `node22-supplement.md`는 고치지 않고 이 파일로 보완한다.

## 1. 남은 위험

**6채널 이상 입력.** sharp 0.35의 기본 제한으로 거부된다. 아래 흐름은 소스 확인 결과이며 실행 시험이 아니다.

| 함수 | 실패 시 사용자에게 보이는 결과 |
|---|---|
| `generateGrowthTimelinePdf` | 사진 없이 진행한다. 표지는 회색 칸이 되고(`functions/src/index.ts:7084`), 본문 카드는 회색 칸에 "사진을 불러오지 못했습니다"를 표시한다(`functions/src/index.ts:7127-7128`). |
| `analyzeFacebookZip` | 해당 썸네일만 빠지고 게시물은 저장된다. 원본 ZIP은 handler 끝에서 삭제되므로(`functions/src/snsAnalyzer.ts:235-236`) **빠진 원본 사진은 복구되지 않는다.** |
| `detectPlantAdvanced` | 원본을 PlantNet으로 보낸다. 독립2 결과의 2절 표를 따른다. |

일반 화면은 사진을 압축한 뒤 보내므로 이런 입력은 드물 것으로 본다. 다만 압축 함수 내부와 운영 입력 분포는 확인되지 않았고 운영 시험도 하지 않았다.

**그 밖의 미해결·미검증**

- JPEG 재인코딩 바이트가 달라질 수 있다. 합성 CMYK에서 미세한 색 변화가 있었다(`232,1,21`→`232,0,0`, `27,60,141`→`28,59,139`).
- 실제 HEVC HEIC 해독과 HEIF 다중 프레임은 시험하지 않았다.
- callable 전체 흐름과 운영 기반 이미지의 네이티브 로딩은 증명되지 않았다.
- `npm audit`의 sharp 항목이 0건이 되었을 뿐이다. 다른 패키지의 권고는 남아 있으며 **전체 보안 해결이 아니다.** sharp 권고의 실제 도달 가능성도 분석되지 않았다.
- 비밀값은 없지만 내부 경로가 기록에 남아 있다. 기존 `prompt.md:1`의 절대 경로에 OS 사용자명이 있다(독립2 1절 5번). `secret-*-1930-failed-raw.json`의 stderr에도 같은 사용자명의 경로가 있다. 기존 원문은 고치지 않는다는 지시와 실패 원문을 숨기지 않는다는 지시에 따라 그대로 두고 여기에 고지한다.

## 2. AI 게이트웨이 동반 배포: 주장과 판정 구분

| 구분 | 내용 | 출처 |
|---|---|---|
| 부모 대조 | `detectPlantAdvanced`의 Gemini 호출은 PR250 AI 창구 이전으로 달라졌지만 회사·모델이 같다. 새 모델 교체와 호출량 증가는 없다. | `control/remaining-deploy-addendum.md`(저장소 미보존) |
| 부모 해석 | "4건도"는 기존 전체 완료 지시의 확장이므로 병합·배포까지 연결된다. | `independent3-question.txt:6` |
| 독립2 판정 | 동작이 동등하고 위험이 낮으며 멈춤 조건도 아니다. 그러나 "**자동 포함으로 보지 않습니다.**" main에서 배포하면 분리할 수 없다. | `independent2-result-original.json` 4절 |
| 독립3 판정 | 부모 해석은 "**성립 가능하지만 유일한 해석은 아닙니다.**" 병합, 3개 함수 배포, AI 창구 동반 배포는 모두 "미확정"이다. | `independent3-result-original.json` 승인 범위 판단 |

부모의 해석은 독립 판정이 아니고, 독립 검토자가 수용하지도 않았다. 동등성 판단은 위험에 관한 것이며 배포 허가가 아니다.

## 3. 승인 범위

- **제품 구현:** 승인(독립2), 독립3이 유지. `871a1f64` 기준, 수정 후 승인 0회.
- **#114 구현·검증·수정:** 범위 안.
- **#319 병합(Hosting 재배포 포함), 3개 함수 운영 배포, AI 창구 동반 배포:** 확정 불가. 허대표님 확인이 필요하다.

코드 승인은 배포 허가가 아니다. **아직 운영 승인을 받지 않았다.** 부모는 3개 PR이 모두 구체적으로 검토 가능한 상태가 되면 병합·배포 범위를 허대표님께 한 번에 묶어 확인할 예정이다. 확인을 받으면 그 답변 원문을 `docs/reviews/`에 남겨야 한다.

선후관계는 [scope-chronology-correction.md](scope-chronology-correction.md)에 따라 사실 근거로 쓰지 않는다. 독립3 근거 가운데 질문의 순서 서술에 기댄 부분도 여기서 사실로 채택하지 않는다. 사용자 실제 문구로 확인되는 것은 `완료바람`과 `4건도 이번에 검증·수정까지 진행`이다.

## 4. 운영 상태

미병합, 미배포, 운영 E2E 미실행이다. **운영 완료가 아니며** 감사 판정은 독립2·3대로 🔍 추가 E2E 필요다.

배포 뒤 필수 확인은 독립2 결과 5절을 그대로 따른다.

- **배포 전:** main SHA, 프로젝트, Node 22, 리전, 함수명, 현재 revision, secret 연결 버전 재확인.
- **배포 후:** `gcloud functions list`, revision, runtime, region, traffic, 소스 버전, cold start 오류 유무 기록.
- **운영 E2E(합성 데이터):** 타임라인 PDF, 식물 감식과 `aiUsageLogs`, Facebook ZIP과 비공개 썸네일.
- **실패 시:** 기록한 이전 revision으로 트래픽 복귀.
