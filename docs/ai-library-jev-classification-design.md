# Jev 목적 분류 실행 설계

2026-11-09. 코드·합성 시험 단계이며 실제 자료 분류 기능이 활성화된 상태가 아니다.

## 이번에 구현한 부분

- `functions/src/aiLibraryJevChoice.ts`: Jev `jev-1.14.0` 고정, 다섯 목적의 Choice 질문과 범위 적합성 Noul 질문, 엄격한 응답 검사. 요청에는 검토된 텍스트와 고정 질문만 포함한다. transport를 명시적으로 주입하지 않으면 실패한다.
- `functions/src/aiLibraryClassification.ts`: 기록별 전송 계획, 신뢰된 서버 승인 확인, 제한된 작업 단위, 트랜잭션 기반 시도 이력, 중복 방지, 예산 제한, 취소·불확실 결과 복구 로직.
- `aiLibraryJevTransport.ts`: 공식 HTTPS endpoint만 사용하는 HTTP transport, 15초 제한, redirect 차단, 64KiB 응답 제한, 엄격한 응답 검사, 자동 재시도 없음. 키·fetch·runtime 검사 함수를 주입받는다.
- `aiLibraryClassificationStore.ts`, `aiLibraryClassificationService.ts`, `aiLibraryClassificationCallable.ts`: 서버 전용 Firestore 이력, 범위·검토·동의·승인·실행·취소·복구·상태 callable 연결. `index.ts`에서 `aiLibraryClassification`을 내보낸다.
- `AiLibraryClassificationPanel.tsx`: 명시적 범위·예산·만료, 전송 본문 검토, 계획 동의, 전체 실행, 일시 중지·취소·새 계획 화면.
- 실제 네트워크 transport까지 연결된 코드지만 운영 실행은 기본 잠금이다. `HARU_TYPESAFE_API_KEY` secret 선언·바인딩 코드만 추가했으며 실제 키 생성·조회·등록, runtime 활성화, 운영 Functions 배포는 하지 않았다. 자동 트리거·스케줄러도 없다.

## 분류 기준

의료신기술은 임상 기술·시험·의료기기·치료법, 건강상식은 일상 건강·예방·영양·운동, 생활정보는 실용적 일상 정보, 투자정보는 시장·증권·자산 투자, AI신기술은 AI 모델·도구·기술 구현을 뜻한다.

의료 AI는 임상 목적이면 의료신기술, AI 기업 주식은 투자 목적이면 투자정보다. 단순 키워드보다 글의 주된 용도를 따른다. 생활정보를 모든 나머지 글의 대체 폴더로 쓰지 않는다. 범위 밖·낮은 확신·혼합 주제·잘못된 응답은 검토 대상으로 남기고 기존 분류를 바꾸지 않는다. 확신 기준은 보수적 개발 정책이며 한국어 실자료 정확도나 확률 보정은 검증하지 않았다.

## 전송과 승인 경계

원문 전체를 먼저 검사한다. 16,000 UTF-8 바이트를 넘거나 비밀값·개인 건강/금융·미성년 관련 정보를 의심하는 자료는 전송 후보에서 제외하고 로컬 검토 대상으로 둔다. 제외되지 않은 텍스트에서도 URL·이메일·일부 날짜·식별 메타데이터를 제거한다. 원문을 조용히 잘라서 일부만 검사하지 않는다.

이 규칙 검사는 개인정보 제거를 보장하지 않는다. 따라서 전송할 각 payload 해시를 명시적으로 검토했다는 서버 측 기록이 추가로 필요하다. 프런트엔드의 승인 불리언은 허가로 인정하지 않는다. 계획은 소유자·기록 ID·전체 원문 해시·전송 텍스트 해시·모델·정책 버전·만료·총예산에 묶인다. 내용이나 계획이 바뀌면 승인도 다시 확인해야 한다.

실행 기능은 기본 비활성이고, 신뢰된 서버 identity/approval/runtime gate가 없으면 호출하지 않는다. 전송 허가와 결과 반영 각각의 트랜잭션 안에서 승인·실행 설정·만료를 재확인한다. 승인/설정 문서의 변경은 이 읽기와 충돌해야 한다. 인증된 개발자 계정의 UID와 서버 전용 승인 저장소에 연결했다. 소유자는 요청 데이터로 받지 않는다. 운영 origin은 `https://haru2026.com`만 허용하고 미리보기·localhost·누락 origin은 차단한다. 에뮬레이터 예외는 서버 의존성 주입과 demo 프로젝트·loopback 호스트 검사를 모두 통과해야 한다.

## 중단·중복·수동 변경 보호

전송 전에 원자적 트랜잭션으로 시도 이력과 비용을 확보한다. 시도 키는 작업 하나에만 묶지 않고 소유자·기록·원문/전송 해시·모델·정책에 묶는다. 예산이나 만료가 다른 새 작업을 만들어도 동일 시도를 자동으로 반복하지 않는다.

전송 허가 트랜잭션은 최신 기록의 존재·원문/전송 해시·수동 결정을 다시 읽는다. 그 전에 삭제·수정·수동 이동된 자료는 전송하지 않는다. 이 트랜잭션의 커밋을 요청 시작으로 정의한다. 그 전에 철회하면 새 허가를 내지 않는다. 이미 허가가 커밋된 요청은 이후 철회로 전송 자체를 되돌릴 수 없지만, 이후 요청 허가와 분류 결과 반영은 차단한다.

전송 중 연결이 끊기거나 결과가 불확실하면 `unknown`으로 남긴다. 자동 재시도와 비용 환불 추정을 하지 않는다. 복구는 진행 중 항목을 불확실 상태로 전환할 뿐 다시 전송하지 않는다. 소유자는 승인이 만료·철회되거나 실행이 비활성화된 뒤에도 자기 작업을 취소·복구할 수 있다. 이 정리는 이미 발생했을 수 있는 비용을 취소하지 않는다.

분류 반영 트랜잭션에서 최신 원문 해시·기록 존재·수동 분류 여부를 재검사한다. 수동으로 미분류로 돌린 결정도 보호한다. 기록에는 분류와 모델·정책·확신·해시만 추가하며 본문·날짜·AI 출처·책 소재는 바꾸지 않는다. 작업 이력에는 원문·프롬프트를 복제하지 않는다. 자동 원상복구나 일괄 재분류 기능은 없다.

Store는 Firestore 트랜잭션에 연결했다. 쓰기를 콜백의 모든 읽기 뒤로 지연하고 전역 시도 키는 `create`로 보존한다. 새 `aiLibraryClassificationPrivate/{uid}` 하위 control·plan·approval·review·job·attempt 문서는 기존 Rules의 기본 거부를 사용하며 클라이언트 접근을 열지 않는다. 기록 본문은 기존 `users/{uid}/records`에만 두고 새 이력에는 복제하지 않는다.

전체 범위는 최대 1,000개다. 1,001번째가 있으면 조용히 자르지 않고 범위를 나누도록 거절한다. 계획은 type-only 목록 조회 후 본문을 10개씩 읽어 해시를 만들고 버린다. 검토는 20개씩 정확한 최소화 본문을 보여주며 전체 적격 해시를 확인해야 승인된다.

화면의 명시적 전체 실행은 1개씩 순차 callable을 보내며 완료·예산·만료·불확실 결과·무진행·중지·취소에서 멈춘다. 새로고침은 자동 실행하지 않는다. sessionStorage에는 계정별 계획 해시만 남긴다. 응답을 잃으면 재전송하지 않고 읽기 전용 상태를 확인한다. 새 계획은 기존 작업의 서버 취소 확인 뒤 로컬 상태만 비운다. 취소는 이력 삭제나 기존 분류 되돌리기가 아니다.

## 비용 제한

공식 공개 가격은 입력 100만 토큰당 $0.042, 출력 무료다. 기본 64k 요청 한도를 보수적으로 65,536토큰으로 잡아 요청당 최소 **2,753 microUSD($0.002753)**를 확보한다. 작은 입력의 바이트 제한은 별도 안전장치이며 정확한 토큰 수 계산이 아니다.

현재 엔진은 성공한 요청도 최대 확보 금액을 계속 사용한 것으로 계산한다. 영수증 기반 정산·미사용분 반환은 구현하지 않았으므로 이 값은 **측정된 과금액이 아닌 보수적 실행 예산**이다. 예산이 부족하면 다음 호출 전에 멈춘다. 실제 평균 비용을 예측한 금액과 실행 한도를 혼동하지 않아야 한다. 향후 가격·요청 한도가 바뀌면 코드와 승인을 다시 검토한다.

## 시험 및 활성화 전 남은 일

`cd functions && npm run test:ai-library-classification`는 현재 TypeScript 소스를 가짜 HTTP·원자적 인메모리 저장소와 함께 시험한다. 대량 합성 자료, 동시 호출, 다른 계획으로 재시도, 승인 누락·만료·철회, 개인정보 검토, 수동 이동·원문 수정·삭제, 비용 한도, 취소와 불확실 복구를 확인한다. 실제 API·Firebase·실자료는 사용하지 않는다. 현재 소스 전용 시험 46개, 기존 Functions 동작·접근 정책 10개, 확장 13개, 프런트엔드 27개가 통과했다.

`test:ai-library-classification:emulator`는 `AI_LIBRARY_TEST_PROJECT=demo-haru-ai-classification`와 loopback `FIRESTORE_EMULATOR_HOST`가 일치할 때만 실행한다. 운영 자격증명 없이 공식 로컬 Firestore 에뮬레이터와 가짜 provider로 저장·재시작·동시성·철회·취소·전송 직전 기록 변경을 검증했다. 6개 시험이 통과했다. 이 시험은 운영 환경 또는 실제 모델 품질 검증의 대체가 아니다.

`frontend/test/ai-library-browser/classification.html`의 실제 React 패널을 Chrome에서 합성 API로 시험했다. 검토·동의·순차 전체 실행·응답 유실·만료·계정 변경·새 계획 20개 검증이 통과했다. 기존 폴더 fixture와 기존 회귀 시험도 별도로 유지한다. Functions 전체 타입검사와 임시 출력 전체 빌드, 프런트엔드 더미 설정 전체 빌드를 확인한다. 프런트엔드 전체 `tsc`는 기존 미수정 `ExportModal.tsx` 구문 오류로 차단되어 새 모듈 개별 타입검사로 보완했다.

독립 검토에서 전송 직전 기록 변경과 새 계획 복귀 경로를 보완했다. 기존 설치 확장·운영 데이터·본인 작업공간은 변경하지 않았다.

활성화하려면 별도로 다음을 확정해야 한다.

1. 정확한 전송 자료·수신 업체(TypeSafe AI)·목적·민감정보 처리와 보존 조건에 대한 승인. 자동 개인정보 검사는 완전하지 않다.
2. 총 실행 예산과 가격·자동충전 영향, 한국어 합성 표본의 실제 모델 품질 검증 범위. 유료 표본 호출도 아직 하지 않았다.
3. 별도 `HARU_TYPESAFE_API_KEY`의 생성·보관·서버 지속적 접근에 대한 승인. 기존 키를 임의로 재사용하지 않는다.
4. 정확한 새 callable 및 필요한 Hosting 배포 범위 승인, 서버 private runtime 설정 검토. main 병합·운영 배포는 이번 PR 갱신 범위가 아니다.
5. 위 조건이 충족된 뒤 시험용 범위부터 정확한 검토·승인·한도에 묶어 실행하고 결과를 확인한다.

공식 문서: [모델·가격](https://docs.typesafe.ai/models), [System One API](https://docs.typesafe.ai/api/system-one), [Choice](https://docs.typesafe.ai/primitives/choice), [Noul](https://docs.typesafe.ai/primitives/noul), [데이터 처리](https://docs.typesafe.ai/legal). 학습에 사용하지 않는다는 설명과 무보관은 다르다. 기본 계정의 ZDR는 확인되지 않았으며 enterprise 대상으로 안내된다.
