# 웹/PWA 디자인 개선 묶음 — 2026-11-18

## 목적과 승인 범위

대표님 승인: 하루lab 공식 로고는 호박, haru2026 서비스 화면과 설치 아이콘은 기존 포도 유지. 이전 진단의 웹/PWA 개선안을 묶어서 구현한다. 기존 미커밋 작업을 보존하기 위해 최신 원격 main 5f0c8a67의 별도 worktree와 codex/pwa-design-bundle-20261118 브랜치를 사용했다.

## 구현

- 하단 메뉴를 홈·나의 기록·함께읽기·더보기 4개로 정리. 기존 재미 영상·구독·설정 및 권한에 따른 개발자 메뉴는 더보기에서 접근. Radix Dialog의 포커스 제한·Escape 닫기를 이용한다.
- 기록 형식 예시를 펼쳐 보는 도움말로 줄이고 입력 라벨·다음 화면에서 확인 후 저장한다는 안내를 유지. 명언 주변 여백과 중복된 하단 여백을 줄임. 사업자 정보는 로그인한 홈에서만 접으며 공개 화면·다른 경로에서는 기본 펼침. 약관·환불·사업자 정보 링크는 항상 제공한다.
- 기존 haru-theme 값을 보존하고 기기 설정/라이트/다크를 선택(저장값이 없으면 라이트). 다크는 홈·나의 기록·함께읽기·설정·작성 화면에만 적용하고 미대응 경로 및 기존 형식 편집창/일반 대화상자는 밝은 화면을 유지한다. 저장된 선호는 경로 이동으로 바꾸지 않는다. 기기 설정을 선택하면 기기 테마 변경을 구독하고 동일 출처 다른 탭의 설정 변경도 반영. 첫 페인트 전 테마를 적용하고 주요 홈·목록·공개 기록·설정·작성·읽기/편집창의 고정 색상을 CSS 역할 토큰으로 연결.
- 화면/매니페스트/테마 색상을 같은 기준으로 맞춤. safe area 상단·하단 여백과 공통 뒤로가기/닫기 44px 영역, 4개 메뉴 68px 높이 반영.
- 홈 화면 추가 기능을 더보기와 설정에 제공. 설치 이벤트가 있으면 사용자 클릭으로 브라우저 설치 창을 열고, 없으면 플랫폼별 설치 도움말을 제공. 설치 완료는 appinstalled/standalone 신호로만 표시.
- PWA 서비스 워커를 명시적으로 등록하고 공개 앱 셸만 미리 캐시. Hosting의 Google 서버 콜백 /oauth/google/callback, Firebase 예약 /__/auth, 인증·결제 SPA 콜백/정적 사이트/파일 경로는 navigation fallback에서 제외. 빌드 SW 시험이 firebase.json의 모든 Functions rewrite를 직접 대조한다. 개인 기록 API 응답은 캐시하지 않음. Firebase Storage는 기존 NetworkOnly 유지.
- 새 버전은 사용자 선택 후에만 활성화. onNeedReload를 탭별 승인과 연결해 다른 탭은 안내만 표시한다. 최초 설치 clientsClaim은 켜되 자동 reload는 하지 않는다. 제어 이벤트가 오지 않으면 12초 후 명시적 재열기 선택을 제공하며 자동 강제 재로드는 하지 않는다. 과거의 전체 SW 등록 해제/캐시 삭제/강제 새로고침 코드는 제거하고 새 캐시 삭제 명령은 추가하지 않음.
- 계정 확인 화면 바깥에 연결 안내를 배치. 상단 safe area는 공통 루트 한 곳에만 적용한다. 하단 메뉴 회피 여백은 푸터까지 포함하는 셸 끝에 둔다. 오프라인 안내의 연결 확인은 화면을 다시 불러오지 않으며 자동 저장·오프라인 저장을 약속하지 않는다.
- 나의 기록 목록에서 당겨서 새로고침과 명시적 새로고침 버튼을 제공. 상단·세로 단일 손가락·임계 거리 조건, 취소/짧은 당김/입력 요소/열린 편집창/중복 실행 차단을 적용한다.

## 검증 근거와 한계

- npm run build: QA 전용 Firebase 환경값으로 성공. 운영 자격 증명·계정·API 호출 없이 번들 검증. 생성물은 배포용으로 사용하지 않는다. 기존 대형 번들/동적 import 관련 경고가 존재한다.
- 최초 확장 단위 검증은 97개 중 91개 통과였고, 검토 수정 후 추가 시험을 포함하면 107개 중 101개 통과다. 성장타임라인 하네스의 기존 6개는 동일하게 실패한다. 변경 전 HEAD의 원본 SayuPage를 주입한 동일 테스트에서도 11개 중 5개 통과/같은 6개 실패(ReferenceError: isSpecialDayRecord is not defined)를 재현. 기존 테스트 결함을 이번 변경의 신규 실패와 구분하며 관련 하네스를 임의 수정하지 않음.
- pwaBuild.test.mjs: 빌드 SW의 실제 navigation denylist, 공개 자산 캐시 범위, 강제 활성화 부재, firebase.json Functions rewrite 제외를 확인하는 4개 시험. 별도 pwaUpdateController·themePreference 시험은 탭별 승인·시간 초과·활성화 실패·기본값·미대응 경로를 확인한다.
- 격리 브라우저: 320/390px와 데스크톱에서 가로 넘침 없음. 라이트/다크, 입력 보존, 형식 선택 후 편집창 전달, 더보기, 설치 도움말, Escape 닫기 확인.
- 연결 이벤트 시뮬레이션에서 안내 표시/복구와 입력 유지 확인. 실제 네트워크 차단·기기 홈 화면 설치 시험을 대신하지 않는다.
- 합성 터치 이벤트로 긴 당김 1회 실행, 짧은 당김/취소/편집 중 실행 0회 확인. 실제 휴대폰 제스처/키보드/노치/상태바는 미확인이다.
- 비서별 모든 개별 화면의 다크 대비 전수검증 및 운영 설치/업데이트/오프라인 E2E는 미실시. 캐시 앱 셸은 이전 온라인 방문/캐시 완료를 전제로 한다. 기록 저장과 AI 사용에는 온라인 연결이 필요하다.
- 첫 두 독립 Claude 실행은 인증/이용 한도로 결과가 없었다. 이후 독립 3차 실행은 수정 후 승인(횟수 1)이며 원문은 docs/reviews/2026-11-18-pwa-design-claude-review-03.md에 보존. Codex 1차 지적 4건과 함께 수정·재검증 후 최신 HEAD 재검토를 받는다. 판정①·운영 완료로 처리하지 않는다.

## 배포 영향과 되돌리기

프론트 Hosting 대상 변경만 있다. Functions 리전 asia-northeast3, Firestore 경로 users/{uid}/records/{date}, Rules, 인증/결제 정책, AI 모델/호출량, 앱 아이콘 자산은 변경하지 않는다. 새 환경변수나 의존성은 없다. 모바일 소스는 수정하지 않는다.

main 병합·Hosting 배포는 이 작업에서 수행하지 않는다. 추후 승인·검토 후 배포하면 기존 사용자는 업데이트 안내를 받는다. 되돌리기는 아래 롤백 보완 절차를 따른다.

## 1차 검토 지적 반영

- Google OAuth 콜백과 Firebase 예약 경로 제외, 실제 Hosting Functions rewrite 자동 대조.
- 다른 탭 업데이트 시 입력 손실 차단. PWA 실제 SW 격리 시험에서 B는 나중에 선택 후 시작 횟수 1·미저장 글 유지, A는 일반 업데이트 후 시작 횟수 3을 확인. 최초 방문의 제어 이벤트 지연은 12초 후 버튼 재활성화·사용자 재확인으로 복구.
- 브라우저 native confirm 자동화가 멈추는 제약은 기록하고, 저장 확인을 접근 가능한 앱 내 Dialog로 전환한 뒤 실제 두 탭 시험을 완료했다.
- 기본 라이트·미대응 경로 라이트 유지·기존 FormatModal/일반 Dialog의 밝은 표면 경계. 시스템 자동 추종은 사용자가 기기 설정을 선택한 지원 경로에서 제공.
- 명언 비활성 탭·홈 비서 카드 대비 개선, 푸터 끝의 메뉴 회피 공간 복구, 상단 inset 중복 제거.
- 320/390px의 실제 iframe 뷰포트에서 푸터를 펼친 뒤 모든 링크가 navTop 위에 있음을 DOM 좌표와 캡처로 확인. 약 정보 실제 컴포넌트를 운영 연결 없는 mock으로 렌더해 다크 선호를 유지하면서 밝게 표시함을 확인.

## 롤백 보완

이 PR은 아직 운영 배포되지 않았다. 최종 배포 후 문제가 생기면 대표 승인 범위와 정확한 배포 버전을 먼저 확인한다. 화면만 문제라면 UI 변경을 되돌리되 서버 OAuth 콜백 제외와 탭별 재로드 승인 같은 안전 수정은 유지하는 복구 빌드를 검토한다. 이전 버전의 autoUpdate/landing-refresh SW로 무작정 되돌리지 않는다. SW 자체 복구가 필요하면 /sw.js의 검토된 복구 버전을 먼저 프리뷰에서 기존 설치 세션→복구 세션 순으로 시험하고, 승인 후 배포한다. 기존 제어 클라이언트는 사용자 저장·업데이트 안내를 거쳐 전환한다. 전체 등록 해제·캐시 삭제·즉시 강제 새로고침·기존 객체 변경은 별도 승인 없는 기본 복구 절차가 아니다. public/sw-landing-refresh.js는 과거 설치 SW의 importScripts 및 이전 버전 재현을 위해 보존하며 새 SW에서는 import하지 않는다.
