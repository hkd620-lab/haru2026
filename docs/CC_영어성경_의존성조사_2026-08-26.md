## 요약 (Executive Summary)

1. **영어성경은 코드상 독립 기능이 아니라 "영어성경학습" 묶음(성경/단어장/영어일기학습)의 일부다.** 라우팅 주석부터 `frontend/src/app/App.tsx:248` "`{/* 영어성경학습 */}`"로 `/bible`, `/vocab`, `/diary-learn` 3개 라우트를 한 묶음으로 등록하고 있고, 실제로 Gemini 호출 함수 6개 중 4개(`generateTTS`, `getWordMeaning`, `getGrammarExplain`, `getVerseQuiz`)를 성경 화면과 영어일기학습 화면이 그대로 공유한다. **Flutter로 성경만 분리하면 이 4개 함수를 그대로 가져가거나, 본체 앱에도 남겨 이중 관리하거나, 복제해야 한다.**
2. **지시서가 가정한 5개 함수 중 `translateToEnglish`는 성경 기능과 무관하다.** 코드 주석(`functions/src/index.ts:7655`)부터 "영어 일기 학습 — 한국어 → 영어 번역"이며, BiblePage.tsx에서는 단 한 번도 호출되지 않는다(`DiaryLearnPage.tsx`에서만 호출). ⚠️ 확인 필요.
3. **지시서에 없던 함수 2개(`getVerseTranslation`, `getVerseWordMapping`)가 성경 기능의 핵심이다.** 성경 구절의 한국어 번역과 단어 매핑을 실시간으로 만들어내는 실제 엔진이며, 둘 다 BiblePage.tsx 전용이다. 이 2개를 빼면 "한국어 대역"이 어떻게 만들어지는지 설명이 안 된다. ⚠️ 확인 필요 (지시서 갱신 필요).
4. **성경 본문은 KJV(공개도메인) 정적 JSON 번들이고, 한국어 대역은 저장된 텍스트가 아니라 매 구절 탭마다 Gemini로 실시간 생성 후 캐시된다.** MVP 방향("영어 KJV 본문 + AI 한국어 학습 번역")과 현재 구현이 정확히 일치한다.
5. **`users/{uid}/bibleWordbook` 경로는 죽은 경로다.** `firestore.rules`와 `accountDeletion.ts`엔 존재하지만, 실제 단어 저장은 `users/{uid}/vocabulary`를 쓴다. ⚠️ 확인 필요.
6. **`users/{uid}/vocabulary` 서브컬렉션은 Firestore 보안규칙에 매칭되는 rule이 없다.** `firestore.rules`엔 루트 컬렉션 `/vocabulary/{docId}`만 있고 서브컬렉션용 rule이나 catch-all이 없어, 이론상 클라이언트 직접 read/write가 거부될 수 있다. 실제 동작 여부는 코드만으로 단정할 수 없어 별도 확인 필요. ⚠️ 확인 필요 (중요도 높음).
7. **성경 관련 Gemini 호출 함수 6개 중 4개는 서버 측 로그인 검증이 없다** (`getWordMeaning`, `getGrammarExplain`, `getVerseQuiz`, `getVerseTranslation`, `getVerseWordMapping`, `translateToEnglish` — TTS와 관리자용 preload만 `request.auth` 체크). 로그인/구독 게이팅은 전부 프론트엔드에도 없다. ⚠️ 확인 필요.
8. **`frontend/src/data/`에 원본과 바이트까지 동일한 중복 JSON 파일 97개**(`파일명 4.json` 95개, `파일명 5.json` 2개)가 존재한다. CLAUDE.md의 "백업 파일 금지" 원칙과 같은 문제 패턴이며, Flutter 앱으로 데이터를 옮길 때 그대로 들고 가면 안 된다. ⚠️ 확인 필요.

- 필드: `word, meaning, example, memo, savedAt`
- `bibleWordbook`은 `firestore.rules:313-316`(규칙 정의됨)과 `functions/src/accountDeletion.ts:135`(탈퇴 시 삭제 대상 목록)에만 존재 — 코드베이스 전체에서 이 경로로 실제 read/write하는 곳 0건 (죽은 경로)
- `vocabulary`는 성경/일기 공용 이름이지만, 실제로 쓰는 곳은 BiblePage뿐이다. `DiaryLearnPage.tsx`의 단어 클릭(`:474-494`)은 뜻 조회만 하고 저장 기능이 없다(저장 버튼/핸들러 없음)
- ⚠️ **`firestore.rules:292-294`의 `/vocabulary/{docId}` 규칙은 루트 컬렉션 기준이라, 실제 경로인 `users/{uid}/vocabulary/{docId}`(서브컬렉션)에는 매칭되지 않는다.** 파일 전체(412줄)를 확인했으나 `users/{userId}/vocabulary` 전용 규칙도, `{document=**}` catch-all도 없다. Firestore 규칙은 기본적으로 매칭되는 규칙이 없으면 거부이므로, 이론상 로그인 사용자의 단어 저장/조회가 클라이언트에서 거부될 가능성이 있다 — **단, 이것은 정적 코드 분석 결과이며 실제 배포 환경에서의 동작(에러 로그, 실사용 확인)은 별도로 검증 필요**.

### grammarCache 컬렉션

- **전역 캐시** (유저별 아님). 문서ID = `verseKey` — 성경은 `{bookPrefix}_{chapter}_{verse}`(예 `genesis_1_1`), 영어일기학습은 `diary_...` 형식을 공유 사용 (`functions/src/index.ts:7195,7396`)
- 문서 구조: `getGrammarExplain`이 생성하는 6개 문법 항목(`verb/preposition/phrasal/relative/question/exclamation` 각각 설명+예문영+예문한) + `mysentence/korean` + `createdAt` + `verifiedByGPT` + `gptChanges[]`
- 클라이언트 직접 read 허용(로그인 시), write는 Functions(Admin SDK)만 가능 — `firestore.rules:244-246`. `diary_` 프리픽스 문서는 클라이언트 직접 read에서 제외됨(규칙에 명시적 정규식 필터)
- CLAUDE.md에 기록된 2026-04-28 "grammarCache 구조 불일치" 장애가 바로 이 컬렉션이다 — 여전히 유저 구분 없는 전역 컬렉션 구조 그대로임을 확인

### 성경 본문 자체 저장 위치

- **정적 JSON 번들 (프론트엔드 빌드에 포함)**. Firestore/Storage/외부 API 실시간 호출이 아님.

## 3. Storage 조사

- TTS 오디오 캐시 존재함. 경로 패턴: **`ttsCache/{cacheKey}_{voice}.mp3`** (Firebase Storage 버킷 루트, `functions/src/index.ts:6984-6985`)
- 방식: **최초 요청 시 생성 후 캐시(on-demand + cache)**. `generateTTS`가 매 호출마다 먼저 `file.exists()`로 캐시를 확인(`:6989`)하고, 없을 때만 OpenAI `tts-1` 호출 후 저장(`:7075-7077`). 사전 생성(batch) 방식의 TTS 함수는 코드 전체에서 발견되지 않음(문법 사전생성 `preloadChapterGrammar`는 텍스트 캐시(`grammarCache`)만 만들고 오디오는 만들지 않음)
- `ttsCache/` 폴더는 **성경 전용이 아니라 4개 기능이 공유**하는 단일 네임스페이스다. 폴더 구조로 기능을 나누지 않고 `cacheKey` 문자열 prefix 관례로만 구분:
  - 성경: `bible_${bookPrefix}_${chapter}_..._${voice}` (`BiblePage.tsx:399,1052,1767` 등)
  - 영어일기학습: `diary_${key}_${text.slice(0,20)}` (`DiaryLearnPage.tsx:320`)
  - 책 리더: `chapter_${chapter.id}` (prefix 관례 없음, `BookReader.tsx:363`)
  - SAYU: 레코드 키를 정제한 문자열 (`SayuPage.tsx` 632-633)
- 성경 기능만 분리할 경우 `ttsCache/bible_*` 패턴만 골라내는 것은 가능하지만, Storage 버킷 자체를 통째로 나눠 갖는 구조는 아니다.

### 로그인 필수 여부 — 필수 아님

- `BiblePage.tsx` 전체에서 `premium`/`subscription`/`구독`/`프리미엄`/`베이직` 키워드 0건

### 서버 측(Functions) 인증 체크

- 6개 성경 관련 Gemini 호출 함수 중 **`generateTTS`(로그인 필수, `:6974`)와 `preloadChapterGrammar`(로그인+관리자 필수, `:7377,7380`)만** `request.auth`를 검사한다.
- `getWordMeaning`, `getGrammarExplain`, `getVerseQuiz`, `getVerseTranslation`, `getVerseWordMapping`, `translateToEnglish`는 **인증 여부와 무관하게 호출 가능**하다(코드상 `request.auth` 참조 없음). 정상 사용자용 앱을 거치지 않고 Firebase 프로젝트 설정값만 알아도 호출은 가능한 구조라는 의미이며, 남용 시 Gemini/OpenAI 비용에 영향을 줄 수 있다.

### 프리미엄 게이팅 / PortOne 구독 연결 여부 — 연결 없음

- `verifyPayment`(`:5232`), `subscribeWithBillingKey`(`:5297`) 등 PortOne 관련 함수를 성경 관련 파일(BiblePage/VocabPage/DiaryLearnPage/GrammarDashboard) 어디에서도 호출하지 않음
