# 개인용 새 수집자료 자동 분류

사용자 승인 원문: “앞으로 새로 수집하는 자료도 Jev로 자동 분류해줘. 확실한 건 폴더에 넣고 애매한 건 추천 분류와 함께 보류로 모아줘. 내가 직접 옮긴 분류는 유지해줘.”
추가 승인: 본문 문단 나누기·첫 줄 들여쓰기 및 확장의 일반/코딩/리서치/글쓰기 대신 새 목적 폴더 선택 저장.

새 `ai_log` 문서 생성 이벤트를 서버에서 처리한다. 활성화 시각 이후 생성된 개발자 계정의 새 자료만 대상이며 기존745건은 재전송하지 않는다. 일반 일기나 다른 회원 자료는 분류하지 않는다. 기존 모델 Jev 1.14.0, 엄격한 Choice/Noul 검사와 전송 전 본문 최소화·검토 제외 기준을 유지한다.

수집기 3.0은 자동 분류/의료신기술/건강상식/생활정보/투자정보/AI신기술/harulab을 선택한다. 추가 사용자 요청 “harulab폴더를 추가 부탁해 현재개발하고 있는 앱관련정보를 정리하고 싶어”에 따라 harulab은 개발 앱 자료를 직접 선택·이동하는 개인 폴더다. Jev의 기존 5개 자동 분류 기준은 그대로 유지한다. 직접 선택은 기존 import의 manual 분류를 사용하며 생성 이벤트가 바로 제외한다. 수집기에는 AI API 키나 공급자 호출을 추가하지 않는다.

처리는 `control/autoNew`가 활성화된 서버 private 설정일 때만 가능하다. 기존 일괄 실행 `control/runtime`은 열지 않는다. 하루 보수적 예약 한도는 $1이며 요청당 $0.002753을 확보한다(실제 청구 예측 아님). 초과·긴 본문·전송 전 검사 대상은 추천 없이 보류한다. 실패/불확실 호출을 자동 재시도하지 않으며 at-least-once 이벤트의 중복은 전역 시도 이력으로 막는다. 다음 날 보류를 자동으로 다시 전송하지 않는다.

전송 직전과 결과 반영 시점에 현재 원문·생성 identity·수동 분류·실행 설정을 트랜잭션으로 재확인한다. 직접 옮기거나 수정한 기록을 덮어쓰지 않는다. 적용 전 분류 스냅샷을 서버에 보존한다. 원문·제목·출처·책 소재·기록 날짜는 변경하지 않는다. 보류 메타데이터는 기존 화면에서 직접 확정할 수 있다.

본문 문단/들여쓰기는 화면 표현만 바꾼다. 저장·해시·복사는 원문을 그대로 사용하며 HTML을 해석하지 않는다.

운영 범위: 새 classifyNewAiLibraryLog 이벤트 함수, saveAiLibraryImport/listAiLibraryLogs/moveAiLibraryLog/listAiLibraryReviews의 6개 폴더 지원과 Hosting, 기존 확장 설치본의 소스 갱신. Rules·회원탈퇴·기존 일괄 분류 callable 배포·새 모델 추가 없음. 새 private 설정 활성화와 소량 합성 이벤트 검증 후 완료한다. 확장 실제 경로와 기존 파일 해시를 확인하고 원본을 보존하며 설정·인증 저장소는 유지한다.
