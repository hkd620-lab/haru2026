# Claude Code 필수 지시문 — HARU2026 Slack 가성비 운영정책 즉시 준수

권장 모델: Claude Sonnet 4.6

이 지시는 지금부터 모든 HARU2026 Claude Code 작업에 의무적으로 적용한다.
저장소에 공식 정책 문서가 병합되기 전에도 즉시 준수하고, 병합 이후에는 `docs/HARU2026_Slack_운영정책.md`를 최우선 기준으로 삼는다.

## 기본 원칙

Slack은 HARU2026의 의사결정·검증·인수인계 장부다.

- GitHub를 코드·커밋·PR의 기준으로 삼는다.
- Firebase와 운영 환경을 배포·운영 상태의 기준으로 삼는다.
- Slack에는 확인된 상태 변화와 다음 행동만 기록한다.

Claude Code는 Slack을 대화 전문, 전체 로그 또는 코드 저장소처럼 사용하지 않는다.

## 공식 채널

- 개발 기록: `#haru2026-개발` (`C0C11P98MHV`)
- 감사·운영·인수인계: `#haru2026-감사` (`C0C1LQ394JY`)

## 작업 시작 시

다음 경우 관련 Slack 기록을 먼저 확인한다.

- 새로운 독립 작업을 시작할 때
- 이전 작업을 인수받을 때
- 현재 PR·배포·감사 상태가 불확실할 때
- 기존 결정과 충돌할 가능성이 있을 때

매 명령이나 매 대화마다 Slack을 반복 검색하지 않는다.
Slack 기록만 믿지 말고 GitHub의 실제 PR·SHA와 운영 환경의 실제 상태를 함께 확인한다.

## 반드시 기록할 상태 변화

- 독립 작업 시작
- 작업 범위 또는 결정 변경
- PR 생성
- 중요한 리뷰 지적
- main 병합
- 배포 성공 또는 실패
- 운영 E2E 완료
- 장애·보안 문제 발견
- 복구 완료
- 최종 완료
- 인수인계
- 허대표님의 결정이 필요한 사안

단순 진행 상황, 일반적인 테스트 실행, AI 답변 완료는 기록 대상이 아니다.

## 기록하면 안 되는 내용

- Claude 답변 전문
- 긴 지시서·감사보고서 전문
- 빌드·테스트 로그 전문
- 코드 diff 전문
- GitHub 자동 알림과 동일한 내용
- 확인되지 않은 추측
- 같은 상태의 반복 게시
- 비밀번호, API 키, 토큰, 인증정보
- 개인정보, 결제정보
- 사용자 첨부파일 내용
- 환경변수와 운영 비밀값 원문

## 메시지 작성 규칙

먼저 해당 작업의 기존 대표 메시지와 스레드를 찾는다.
동일 작업의 후속 상태는 스레드 답글로 작성한다. 다음 경우에만 새 최상위 메시지를 작성한다.

- 최종 완료
- 감사 판정 변경
- 새로운 장애
- 독립된 새 작업

메시지는 원칙적으로 5~7개 항목, 한글 약 700자 이내로 작성한다.

```
[작업명 — 현재 상태]
• 판정:
• 기준 PR·SHA:
• 확인 결과:
• 배포·운영 상태:
• 남은 일:
• 다음 행동:
```

PR 링크, 커밋 SHA, 배포 대상처럼 검증 가능한 근거가 있으면 포함한다.

## 판정 권한

Claude Code는 자신이 수행하거나 직접 확인한 개발 사실만 보고한다.
다음 사항을 임의로 확정하지 않는다.

- 감사 최종 통과
- 운영 최종 정상
- 프로젝트 전체 완료
- 허대표님의 승인

공식 감사 판정은 검토자가 증거를 확인한 후 확정한다.
PR 생성, 테스트 통과, main 병합, 배포, 운영 E2E는 각각 별도 상태로 구분한다.

## Slack 접근 실패 시

Slack을 실제로 읽거나 게시하지 못했다면 성공한 것처럼 표현하지 않는다.
최종 보고에 반드시 다음을 포함한다.

- Slack 확인 여부: 미확인
- Slack 게시 여부: 미게시
- 실패 원인
- 사람이 그대로 게시할 수 있는 `Slack 기록용 확정 요약`

## 최종 응답 필수 항목

모든 주요 작업의 최종 응답에 다음을 포함한다.

- 기준 브랜치·SHA
- 변경 및 검증 결과
- PR·병합·배포·운영 상태의 구분
- 남은 작업과 다음 담당자
- Slack 확인 여부
- Slack 게시 여부
- 게시했다면 채널과 메시지 링크
- 게시하지 못했다면 `Slack 기록용 확정 요약`

## 즉시 적용 범위

이 지시는 Slack 사용 방법에 관한 운영 지시다.
별도의 코드 수정 지시가 없다면 이 지시만을 이유로 저장소 파일을 수정하거나 커밋·PR·배포하지 않는다. 저장소 정책 파일 수정은 기장에게 별도로 부여된 작업 지시에 따른다.
