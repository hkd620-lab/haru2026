# 🧭 지시서 — 하루식물탐정 역지오코딩 연결 (CFM 실행용)

CI(검토)가 코드를 다 뜯어봤어. **새로 만들 건 하나도 없어.** 성장타임라인에 이미 돌아가는 역지오코딩을 하루식물탐정에 "연결만" 하면 돼. 검증된 패턴(`GrowthTimelineCreator.tsx`)을 그대로 베껴오는 작업이라 안전해.

- 브랜치: `feature/new-formats`에서 작업 → 끝나면 `main` 머지·배포 (프로젝트 원칙)
- 개인정보: 공개도감엔 지역명만, 정밀좌표·도로명은 본인만

## 핵심 원칙 (이거 어기면 망함)

1. ⚠️ **압축 전 원본 `file`에서 EXIF를 읽어라.** 압축(`createPlantImageVariants`)하면 GPS가 날아간다. `readOriginalImageMeta(file)`는 반드시 압축 *앞단*에서 호출.
2. ⚠️ **GPS 없는 사진(스크린샷·카톡사진·위치권한OFF·도감이미지)에서 절대 안 깨지게.** `hasGps` 분기 + 좌표 없으면 위치 없이 그냥 진행.
3. ⚠️ **개인정보** — 공개도감엔 **지역명(regionLabel, 구/동 수준)만**. 정밀좌표·도로명(roadAddress)은 본인에게만. (이미 코드에 있는 "좌표·상세주소 비공개" 원칙 유지)
4. 요청 범위만. 기존 함수·import 손대지 말고 **추가 위주.**

## 작업 4단계

### ① import 추가 (파일 상단, 15행 근처 기존 import 아래)

```ts
import { readOriginalImageMeta } from '../services/photoMetadataService';
import { getLocationCandidateFromGps, type ReverseGeocodeCandidate } from '../services/reverseGeocodeService';
```

### ② 타입에 위치 필드 추가

`PhotoItem` 타입(103행)에 추가:

```ts
  latitude?: number;
  longitude?: number;
  locationLabel?: string;   // 본인용: 지번/도로명 포함 가능
  regionLabel?: string;     // 공개용: 구/동 수준만
```

같은 식으로 **`PlantImageMeta` 타입(119행)에도** `latitude?` / `longitude?` / `locationLabel?` / `regionLabel?` 추가.

### ③ 업로드 핸들러 `handleFileChange`(764행)에서 EXIF 읽고 역지오코딩 호출

`const { original, thumbnail } = await createPlantImageVariants(file);` **바로 위**에 아래를 넣어라(원본 file 기준!). 검증된 패턴(`GrowthTimelineCreator.tsx` 270~290행) 그대로:

```ts
const meta = await readOriginalImageMeta(file);
const latitude = typeof meta.latitude === 'number' ? meta.latitude : undefined;
const longitude = typeof meta.longitude === 'number' ? meta.longitude : undefined;
let locationLabel: string | undefined;
let regionLabel: string | undefined;
if (typeof latitude === 'number' && typeof longitude === 'number') {
  try {
    const cand: ReverseGeocodeCandidate | null = await getLocationCandidateFromGps(latitude, longitude);
    if (cand) {
      regionLabel = cand.regionLabel;                                       // 공개용
      locationLabel = cand.roadAddress || cand.jibunAddress || cand.regionLabel; // 본인용
    }
  } catch (e) { console.warn('식물탐정 촬영장소 확인 실패'); }              // 실패해도 진행
}
```

그리고 그 아래 `next.push({ ... })` 객체에 `latitude, longitude, locationLabel, regionLabel` 4개를 추가.

### ④ 저장 시 위치를 같이 저장

`PlantImageMeta`를 만들어 push하는 두 곳(대략 1198~1232행, 1269~1323행)에서 각 meta 객체에 해당 PhotoItem의 `latitude / longitude / locationLabel / regionLabel`을 넣어라. `buildResultSaveFields`(1326행)에서도 대표 위치를 결과에 실어주면 끝.

> 표시 그릇(`getPublicCatalogLocationText`, 3809행)은 이미 `locationLabel`을 읽고 있어서, 데이터만 채우면 화면에 자동 노출됨. 새로 안 만들어도 됨.

## 점검 (CLAUDE.md 순서대로)

1. `npm run build` — 오류 0 확인 (오류 나면 중단·보고).
2. 영향 파일: `PlantDetectivePage.tsx` 단일. 8개 페이지 import/라우팅 영향 없음.
3. Firestore 경로 `users/{uid}/records/{date}` 유지 — 위치는 기존 `imageMetas`/결과필드에 **추가**만, 경로 변경 없음.
4. **GPS 없는 사진 1장 + GPS 있는 사진 1장** 섞어 업로드 → 안 깨지고, GPS 있는 것만 지역명 뜨는지 로컬 확인.

## 멈추고 보고할 상황

- `npm run build` 오류
- EXIF가 압축 후에 읽혀 GPS가 항상 비는 경우(원칙 ① 위반 의심)
- 공개도감에 도로명/정밀좌표가 노출되는 경우(원칙 ③ 위반)
