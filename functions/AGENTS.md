# HARU2026 Functions 작업 지침 — 하루LAW Gemini 모델 운영 원칙

이 문서는 `functions/` 영역에서 하루LAW 및 Gemini 모델 관련 작업을 수행하는 기장(Codex)에게 적용되는 강제 운영 규칙이다.
루트 `AGENTS.md`의 기존 규칙을 모두 그대로 따르며, 아래 규칙은 하루LAW/Gemini 관련 추가 제약으로 적용한다.

## ⚠️ 하루LAW Gemini 모델 운영 원칙 — 허대표님 확정 사항 (2026-08-10)

다음 원칙은 허대표님의 명시적 변경 승인 전까지 임의 변경하지 않는다.

### 1. 법률 사실의 원천

- 하루LAW에서 법률 사실의 1차 원천은 국가법령정보센터 등 공식·공공 법률 데이터/API이다.
- Gemini는 법령·판례·공식 자료를 임의 생성하는 사실 원천으로 사용하지 않는다.
- Gemini의 역할은 공식 데이터의 검색 보조, 관련 조문 선별, 정리, 해석, 사용자 설명이다.
- 기존 국가법령정보 OpenAPI 연동 구조를 모델 교체를 이유로 제거하거나 우회하지 않는다.

### 2. 기본 모델 라우팅

하루LAW 및 관련 Functions의 목표 모델 구조는 다음을 기본으로 한다.

- 경량 처리: `gemini-3.5-flash-lite`
  - 법령명/검색어 추출
  - 관련 조문 선별
  - 키워드 추출
  - 구조화/분류 등 저비용·대량 처리
- 고급 법률 설명·복합 추론: `gemini-3.6-flash`
  - 공식 법령/판례를 바탕으로 한 최종 설명
  - 쟁점 정리
  - 복합적인 추가 질문
  - 고위험 법률 질의의 설명 단계
- 특수 고난도 검증 후보: `gemini-3.1-pro-preview`
  - 기본 운영 모델로 자동 채택하지 않는다.
  - `gemini-3.6-flash`보다 실제 하루LAW 회귀테스트에서 명확한 우위가 확인된 경우에만 제한적으로 검토한다.

### 3. Preview 모델 고정 사용 금지

- Preview 모델을 하루LAW 전체의 장기 기본 모델로 임의 지정하지 않는다.
- Preview 모델 도입·확대는 반드시 실제 회귀테스트 결과와 허대표님 승인을 거친다.
- 모델 이름이 `Pro`라는 이유만으로 `Flash`보다 우수하다고 단정하지 않는다.

### 4. 모델 교체 절차 — 테스트 없이 바로 교체 금지

하루LAW의 답변 품질에 영향을 주는 Gemini 모델 변경은 다음 순서를 지킨다.

1. 현재 실제 호출 지점과 모델명을 먼저 확인한다.
2. 기존 모델의 회귀테스트 결과를 기준점으로 보존한다.
3. 후보 모델을 동일한 테스트 세트로 비교한다.
4. 정확성, 환각, 성급한 결론, 결론 유보, 법률 사실 누락, 답변 안정성을 비교한다.
5. 허대표님에게 결과를 보고한다.
6. 허대표님 승인 후 실제 운영 모델을 변경한다.

모델 문자열만 즉시 치환해서 배포하지 않는다.

### 5. 하루LAW 회귀테스트 필수 평가 항목

최소 다음을 확인한다.

- 사실관계가 부족할 때 성급하게 결론 내리지 않는가
- 제공되지 않은 사실을 임의 추정하지 않는가
- 존재하지 않는 법률·판례·절차를 만들지 않는가
- 기한·송달·서류·요건 등 중요한 사실을 놓치지 않는가
- 법률 판단과 참고 안내를 구분하는가
- 공식 자료 확인이 필요한 경우 이를 식별하는가
- 승소 가능성·위법 여부 등을 과도하게 단정하지 않는가
- 같은 질문에 대한 핵심 판단이 안정적인가

### 6. 고위험 하루LAW 추가질문 처리

- 하루LAW는 고위험 법률 영역으로 취급한다.
- 일반 기록용 경량 모델을 그대로 재사용하는 구조를 당연한 기본값으로 보지 않는다.
- 하루LAW 추가질문/후속대화의 최종 설명 단계는 `gemini-3.6-flash` 사용을 우선 검증한다.
- 단, 실제 코드 반영 전에는 기존 회귀테스트를 통과해야 한다.

### 7. Google 모델 상태 확인 의무

Gemini 모델을 새로 도입하거나 교체하기 전에는 Google 공식 문서에서 아래를 확인한다.

- 정확한 API 모델 ID
- GA / Preview 상태
- 종료/deprecation 여부
- 공식 권장 후속 모델
- 지원 기능 및 파라미터 변경

기억이나 과거 문서만으로 모델명을 추정하여 코드에 넣지 않는다.
404가 발생한 모델명은 임의 추측으로 재시도하지 않고 공식 문서에서 먼저 확인한다.

### 8. 구형 파라미터 및 SDK 호환성 점검

새 Gemini 모델 도입 시 다음을 반드시 확인한다.

- `temperature`
- `top_p`
- `top_k`
- prefilled model turn
- 사용하는 Gemini SDK 버전
- thinking 설정
- structured output / function calling 호환성

deprecated 또는 무시되는 파라미터를 기존 설정 그대로 복사하지 않는다.

### 9. 금지 사항

허대표님 승인 없이 다음을 하지 않는다.

- 하루LAW의 국가법령정보 OpenAPI 제거
- 법률 사실을 Gemini 단독 생성으로 대체
- `gemini-3.1-pro-preview`를 전체 기본 모델로 고정
- 비용 절감만을 이유로 법률 최종 설명 모델을 임의 다운그레이드
- 회귀테스트 없이 모델 교체 후 main 반영/운영 배포
- 다른 HARU AI 비서까지 함께 일괄 모델 교체
- 요청 범위 밖 프롬프트·저장 구조·Firestore 경로·라우팅 리팩터링

### 10. 현재 교체 우선순위

현재 코드에 구형 Gemini 모델이 남아 있는 경우 다음 원칙으로 처리한다.

1. 종료/deprecation이 임박한 모델 사용 지점을 우선 식별한다.
2. 하루LAW의 기존 결과를 회귀 기준점으로 확보한다.
3. `gemini-3.6-flash`를 우선 운영 후보로 비교한다.
4. `gemini-3.1-pro-preview`는 고난도 비교 후보로만 함께 평가한다.
5. 경량 단계는 `gemini-3.5-flash-lite` 전환을 별도 검증한다.
6. 테스트 결과와 허대표님 승인 전에는 운영 배포하지 않는다.

## 최종 원칙

> 하루LAW는 "최신 모델을 쓰는 기능"이 아니라 "공식 법률 데이터를 바탕으로 안전하게 설명하는 기능"이다.
>
> 모델명보다 사실 근거, 환각 방지, 결론 유보, 회귀테스트를 우선한다.
>
> `gemini-3.5-flash-lite + gemini-3.6-flash`를 장기 운영 중심축으로 검증하고,
> `gemini-3.1-pro-preview`는 실제 우위가 증명된 경우에만 제한적으로 사용한다.
